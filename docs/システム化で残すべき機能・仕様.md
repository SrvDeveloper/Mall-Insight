# システム化で残すべき機能・仕様

## 1. 文書の目的

本書は、`現行販売試算_仕様書.md`に記載された現行Excelの仕様を基に、Mall Insightへシステム化する際に残すべき業務機能・計算仕様・データ・画面要件を整理したものである。

現行Excelの不具合や手作業そのものを無条件に再現するのではなく、次の3区分で扱う。

| 区分    | 方針                            |
| ----- | ----------------------------- |
| 継承必須  | 現行業務を継続するため、本番機能として残す         |
| 移行時再現 | Excelとの照合に必要なため「現行再現モード」として残す |
| 非継承   | 数式エラー、固定セル依存、表示期間不足などの欠陥は残さない |

## 2. システム化後も残す業務の全体像

システム化後も、次の業務の流れを維持する。

1. 売上実績・売上予測を基に在庫確保対象の品番を選ぶ。
2. 対象品番に優先順位を付け、必要に応じて追加・差し替え・除外する。
3. 品番単位の年間販売想定を設定する。
4. 年間販売想定をカラー・度数別のSKUへ配分する。
5. 年間販売想定を月別の需要へ配分する。
6. SKU・月別の現在庫と入荷予定を反映する。
7. 月次の将来在庫を計算する。
8. 欠品候補を警告表示し、対応対象を確認する。
9. 手動調整や前提変更の理由を記録する。

## 3. 継承必須の機能・仕様

### 3.1 品番・SKUの階層管理

品番からSKU明細へ展開して確認できる構造を残す。

```text
品番
  └─ カラー
       └─ 度数（SKU）
```

最低限、次の項目を管理する。

| 単位 | 必須項目 |
|---|---|
| 品番 | 社内品番、商品名、カテゴリー、販売状態、優先順位 |
| SKU | 品番、カラー、度数、JAN、モールSKU |
| 商品関係 | 代替品、後継品、仕様替え、終売の状態 |

現行の「優先順位1～24の固定枠」は上限としては残さず、品番数を動的に増減できるようにする。ただし、品番ヘッダーとSKU明細をまとめて表示する見せ方は維持する。

### 3.2 在庫の統合表示

複数拠点・販売チャネルの在庫をSKU単位で集約して表示する。

最低限、次の在庫区分を残す。

- フリー在庫
- 楽天・Yahoo!・au PAY側在庫（現行RSL区分）
- Amazon FBA在庫
- ECストック
- EC合計
- 全体の利用可能在庫

現行のEC合計は、原則として次の考え方である。

```text
EC合計 = 楽天・Yahoo!・au PAY在庫 + Amazon FBA在庫 + ECストック
初期在庫 = フリー在庫 + EC合計
```

各在庫は、取得日時、取得元、手入力か自動取得かを識別できるようにする。

### 3.3 在庫確保対象品番と優先順位の管理

現行の`差し替え品番`が担う次の機能を残す。

- 在庫確保対象品番の一覧
- 品番ごとの優先順位
- 適用開始時期ごとの差し替え
- 手動追加・手動除外
- 上位品番、追加確認品番、除外品番の区分
- 差し替え・調整理由の記録

現行は選定・転記が手作業であるため、移行初期は手動選定を可能とする。将来の自動ランキングを導入しても、担当者が理由付きで追加・除外・順位調整できる機能は残す。

### 3.4 年間販売想定の管理

品番単位で次の値を保持する。

- 基準年間販売数
- 調整後年間販売想定数
- 年間売上額または年間売上想定額
- 設定根拠・コメント
- 設定者、設定日時、適用期間

現行の基本的なSKU配分式を、移行照合および初期算出方法として残す。

```text
SKU年間販売想定数
= SKU基準販売数 ×（品番年間販売想定数 ÷ 品番基準年間販売数）
```

この式は、基準年のカラー・度数構成比を将来へ引き伸ばす方式である。SKU別の手動上書きも許可するが、計算値と上書き値を区別し、上書き理由を必須とする。

### 3.5 月別需要への配分

年間販売想定を月別需要へ配分する考え方を残す。

```text
SKU月別必要数 = SKU年間販売想定数 × カテゴリー月別販売比率
```

現行のカテゴリー区分は次の4種類である。

- 老眼
- PCサングラス
- 調光老眼
- 既成近眼

カテゴリー別に4月から翌3月までの月別比率を保持し、商品ごとに適用カテゴリーを設定できるようにする。比率は年度・適用期間を持つマスタとして管理する。

### 3.6 SKU・月別の入荷予定

SKU・月単位で入荷予定数を登録し、将来在庫へ反映する機能を残す。

最低限、次の情報を扱う。

- SKU
- 入荷予定年月または予定日
- 入荷予定数量
- コメント・補充完了メモ

現行の自由記述を失わないよう、構造化された入荷予定とは別に注記欄も用意する。

### 3.7 月次の将来在庫推移

現在庫、月別必要数、入荷予定から、SKUごとの将来在庫を連続計算する機能を残す。

現行計算式は次のとおりである。

```text
初月残数 = フリー在庫 + EC合計 - 当月必要数 + 当月入荷予定数
翌月残数 = 前月残数 - 当月必要数 + 当月入荷予定数
```

画面では、品番からカラー・度数へ展開し、月別に少なくとも次の値を確認できるようにする。

- 必要数
- 入荷予定数
- 月末残数
- 注記

### 3.8 欠品候補の警告表示

将来残数に基づき、欠品候補を視覚的に識別できる機能を残す。

現行の判定条件は次のとおりである。

```text
将来残数 < 1 → 欠品警告
```

現行再現ではこの条件を使う。本番画面でも警告色による識別を残し、品番・SKU・対象月まで絞り込めるようにする。

### 3.9 品番合計・SKU明細の確認

品番ヘッダーで合計値を確認し、その下でSKU明細を確認できる機能を残す。

品番単位では少なくとも次を集計する。

- 基準年間販売数
- 年間販売想定数
- 年間売上想定額
- 現在庫
- 月別必要数
- 月別入荷予定数
- 月別将来残数または不足数

集計対象は行番号の個別指定ではなく、品番とSKUの関係から動的に求める。

### 3.10 コメント・調整理由・履歴

現行Excelでコメント、注記、テキストボックス、固定値上書きにより管理している判断情報を、検索可能なデータとして残す。

記録対象は次のとおりである。

- 品番選定・差し替え理由
- 年間販売想定の調整理由
- SKU別需要の上書き理由
- 入荷・発注に関する注記
- 仕様変更、終売、後継品等の注記
- 変更前後の値
- 変更者、変更日時
- 適用開始日・終了日

### 3.11 試算条件と結果の保存

過去時点の試算を再現できるよう、試算をバージョン単位で保存する。

最低限、次の情報を同一バージョンとして保持する。

- 基準日または基準月
- 対象品番と優先順位
- 年間販売想定
- 月別販売比率
- 現在庫
- 入荷予定
- 月別需要
- 将来在庫
- 手動調整値と理由

## 4. 移行時に残す現行再現モード

本番の改善ロジックとは別に、移行時の照合用として現行Excelと同じ計算を行うモードを用意する。

### 4.1 再現対象

- 品番年間販売想定数の手入力
- 基準年構成比によるSKU年間販売想定数の配分
- 4カテゴリーの既存月別販売比率による月別配分
- `フリー在庫 + EC合計 - 必要数 + 入荷予定`による連続残数計算
- 将来残数1未満の警告
- 小数を保持した計算結果

### 4.2 代表照合値

`fisi-05`の代表例について、次の結果と一致することを移行受入条件とする。

```text
品番基準年間販売数 = 1,314
品番年間販売想定数 = 3,500
SKU基準販売数 = 48
SKU年間販売想定数 = 48 × 3,500 ÷ 1,314
                    = 127.853881...
2026年7月必要数 = 127.853881... × 8%
                  = 10.228310...
初期在庫 = フリー在庫3 + EC合計35
         = 38
2026年7月入荷予定 = 20
2026年7月末残数 = 38 - 10.228310... + 20
                  = 47.771689...
```

## 5. 画面として残すべき表示・操作

### 5.1 在庫リスク一覧

少なくとも次を一覧表示する。

- 優先順位
- 品番、商品名、カテゴリー
- 現在庫と在庫内訳
- 年間販売想定数
- 入荷予定
- 月別必要数
- 対象期間の最小将来在庫
- 最初の欠品警告月
- 手動調整の有無と理由

欠品警告あり、優先順位、カテゴリー、品番、担当者等で絞り込めるようにする。

### 5.2 SKU別在庫推移

- 品番からカラー・度数への展開表示
- 月別の必要数、入荷予定数、将来残数
- 在庫区分別の内訳
- 欠品警告の色分け
- 注記の表示・編集
- 試算バージョンの切り替え

### 5.3 前提・監査画面

- 入力値と計算値の区別
- 自動取得値と手入力値の区別
- 計算根拠の表示
- 上書き前後の値と理由
- 変更者・変更日時
- 元データへの追跡
- データ欠損、数式相当の計算エラー、古い在庫情報の警告

## 6. 保持すべき主要データ

| データ | 主な項目 |
|---|---|
| 商品 | 品番、商品名、カテゴリー、販売状態、代替・後継品 |
| SKU | 品番、カラー、度数、JAN、モールSKU |
| 販売チャネル | Amazon、楽天、Yahoo!、au PAY、社内・フリー在庫等 |
| 売上実績 | 日付、チャネル、SKU、販売数、返品数、売上、粗利 |
| 在庫スナップショット | 取得日時、拠点・チャネル、SKU、販売可能数、引当数、入庫待ち数 |
| 入荷予定 | SKU、予定日、予定数量、注記 |
| 予測前提 | 対象期間、年間販売想定、月別比率、手動補正、理由 |
| 需要予測 | SKU、対象月、必要数、試算バージョン |
| 在庫予測 | SKU、対象月、期首在庫、入荷、需要、期末残数、警告 |
| 優先順位 | 基準日、品番、順位、追加・除外区分、理由 |

## 7. そのまま引き継がない仕様・不具合

次の項目は現行業務の目的ではなく、Excelの制約・不整合・データ品質問題であるため、本番仕様として残さない。

| 現行の状態 | システム化での扱い |
|---|---|
| 合計行42セルの`#REF!` | 修復し、エラーを検知・通知する |
| 旧シート217セルの`#REF!` | 現行仕様の根拠にせず、必要なら参照資料として隔離する |
| 年間販売想定、月別必要数、将来残数に数式と固定値が混在 | 計算値と手動上書きを分離し、下流を必ず再計算する |
| 行番号を個別加算する合計式 | データ関係に基づく動的集計へ変更する |
| 24品番の固定枠 | 件数を動的にする |
| 現行画面が2026年7月～2027年3月の9か月固定 | 期間を固定列にせず、基準月から動的に生成する |
| 日付見出しの重複・誤記 | 年月をデータとして一意に管理する |
| 存在しない比率セル`BA425`への参照 | 参照整合性チェックを行い、欠損を0として黙って処理しない |
| 月別比率合計が100%と一致しない | 本番計算では妥当性検証を行う。現行再現モードのみ元比率を使用できるようにする |
| 負の在庫を翌月へ持ち越す | 本番では実在庫と未充足需要を分離する。現行再現モードのみ負数残数を許可する |
| 注記やテキストボックスだけで入荷・発注情報を管理 | 構造化項目と自由記述を併用する |
| 売上ランキングを値貼り付けし、各シートへ手動転記 | データから再計算可能にし、手動変更は履歴化する |

## 8. 実装前に確定が必要な業務ルール

次の事項は現行Excelだけでは確定できないため、業務担当者への確認後に本番仕様を決定する。

1. 売上上位品番の順位指標を、純売上、販売数量、粗利のどれにするか。
2. ランキングの集計期間と、前年同期を含めるか。
3. 上位件数を20件固定とするか、設定可能にするか。
4. 「4か月以内」の終点を、4か月目の月末とするか、基準日から120日とするか。
5. 欠品判定を、在庫0、在庫1未満、安全在庫未満のどれにするか。
6. フリー在庫を全量販売可能とするか、他用途の引当を差し引くか。
7. 入荷予定のうち、発注済み、生産中、未発注、確定、未確定をどこまで計算へ含めるか。
8. 年間販売想定数を決める販売実績期間と計算根拠。
9. 欠品中の販売実績を需要へ補正する方法。
10. 新商品、終売品、仕様替え、後継品、セット品の扱い。
11. SKU別の発注ロット、ケース入数、最小発注数、数量丸め方法。
12. 手動上書きが可能な利用者、承認要否、承認フロー。

## 9. 最低限の受入条件

### 9.1 現行業務継続

- 品番からカラー・度数別SKUへ展開して確認できる。
- フリー在庫と各EC在庫を統合表示できる。
- 品番年間販売想定をSKU・月別必要数へ配分できる。
- SKU・月別の入荷予定を登録できる。
- 月次の将来在庫を連続計算できる。
- 将来残数1未満を警告表示できる。
- 優先品番の追加・差し替え・除外と理由を保存できる。
- 手動上書きの前後値、変更者、変更日時、理由を確認できる。

### 9.2 移行照合

- `fisi-05`の代表計算が現行Excelと一致する。
- 同じ入力・前提・対象年月で、品番合計とSKU明細を比較できる。
- 現行再現モードと本番計算の結果を区別して表示できる。
- 試算バージョンを保存し、後日同じ条件を再現できる。

### 9.3 データ品質

- 存在しない参照や欠損データを検知できる。
- 手入力値、自動取得値、計算値、上書き値を識別できる。
- 集計対象の追加・削除・順位変更で合計が壊れない。
- 入力変更後、関連するSKU需要・月別需要・将来在庫が再計算される。

## 10. まとめ

システム化で最も重要なのは、現行Excelの「品番・SKU単位で需要、在庫、入荷、将来残数を一画面で確認し、欠品候補を見つける」という業務価値を維持することである。

一方、固定セル、値貼り付け、9か月固定表示、負在庫の持ち越し、参照エラーは業務要件ではないため引き継がない。移行時には現行再現モードでExcelとの数値照合を可能にし、本番運用では再計算性、履歴、監査性、データ品質を備えた機能へ置き換える。
