## 2. 結論

現行 Excel は、商品・カラー・度数ごとに現在庫、月別需要、入荷予定、将来残数を横並びで確認し、欠品候補を色で見つける用途には有効である。一方、**必要在庫数や発注数を自動決定する仕組みとして、そのままシステム化するのは妥当ではない**。

主な理由は次のとおりである。

1. 年間販売想定数の決定が手入力中心で、販売ペースの算出期間と根拠が一貫して記録されていない。
2. 欠品期間を補正せず販売実績を需要とみなすため、欠品商品ほど将来需要を過小評価し得る。
3. 安全在庫、調達リードタイム、リードタイム変動、発注残の確度を計算に含めていない。
4. 月別季節性は考慮しているが、4カテゴリーの固定比率であり、商品固有の季節性や販促影響を扱わない。
5. 数式セルと固定値セルが混在し、前提を変更しても全体が再計算されない。
6. 現行シートの将来在庫表示は、現在のレイアウトでは12か月ではなく2026年7月から2027年3月までの9か月である。
7. 売上上位品番の選定は手作業で、上位20件の自動抽出や4か月以内の欠品判定式は存在しない。
8. 現行シートの集計行には42セルの `#REF!` が残っている。

したがって、システム化では次の二段階を推奨する。

- **現行再現モード**: 現在のExcelと同じ入力・計算を再現し、移行時の照合を可能にする。
- **改善モード**: 欠品補正、需要予測、安全在庫、リードタイム、確定入荷予定を使って必要在庫・発注推奨数を算出する。

## 4. 現行業務フロー

現行ブックから読み取れる業務フローは次のとおりである。

1. 売上実績または売上予測金額を見て、在庫確保対象品番を手動選定する。
2. `差し替え品番` で対象品番と優先順位を更新する。
3. 主シートに商品別の年間販売数、年間販売想定数、現在庫を入力する。
4. 商品をカラー・度数別に展開し、年間販売想定数を各SKUへ配分する。
5. `月別販売比率` のカテゴリー別構成比で、SKUの年間販売想定数を月別必要数へ配分する。
6. SKU・月別に入荷予定数を入力する。
7. 現在庫から月別必要数を減算し、入荷予定数を加算して将来残数を計算する。
8. 将来残数が1未満となるセルをピンク表示し、欠品候補を目視確認する。
9. 入荷時期・発注要否・仕様変更等をコメントまたはテキストボックスで手動管理する。

## 5. 主シート `在庫推移 (2026.08～)` の仕様

### 5.1 データ粒度

データは次の階層で管理される。

```text
品番
  └─ カラー
       └─ 度数（SKU相当）
```

- 品番ヘッダー行に優先順位、品番、年間合計、品番合計在庫等を置く。
- その下にカラー・度数ごとの明細行を置く。
- 入荷予定はSKU・月単位で入力する。
- 主シートには優先順位1～24の品番枠がある。
- 年間販売想定数が入っている品番は18品番で、残りは新規・確認用の空枠またはゼロ値である。

### 5.3 年間販売想定数の算出

品番ヘッダーの年間販売想定数 `H` は手入力である。例として、`fisi-05` は次の値を持つ。

| セル | 意味 | 値 |
|---|---|---:|
| F6 | 基準年間販売数 | 1,314 |
| H6 | 調整後年間販売想定数 | 3,500 |

カラー・度数明細の基本式は次のとおりである。

```excel
H明細 = F明細 × (H品番合計 ÷ F品番合計)
```

実例:

```excel
H7 = F7 * ($H$6 / $F$6)
   = 48 * (3,500 / 1,314)
   = 127.853881...
```

この式は、基準年のカラー・度数構成比をそのまま将来へ引き伸ばす方式である。

ただし、現行主シートではこの式が一貫していない。年間販売想定数を持つ18品番・194明細行のうち、H列が数式なのは52行、固定値なのは142行である。このため、品番合計のHを変更しても、多くのSKU明細は自動更新されない。

### 5.4 月別必要数の算出

基本式は次のとおりである。

```excel
月別必要数 = SKU年間販売想定数 × カテゴリー月別販売比率
```

実例:

```excel
CI7 = H7 * '月別販売比率'!R21
```

`CI` は2026年7月の必要数で、`R21` は「老眼」カテゴリーの7月比率8%である。

```text
127.853881... × 8% = 10.228310...
```

主シートの月別必要数領域は `AS, AU, AW, ... , CY` の30列で、隣の `AT, AV, AX, ... , CZ` が入荷予定である。

数式参照が確認できるカテゴリー行は次のとおりである。

| 行 | カテゴリー | 期間 |
|---:|---|---|
| 5 | 老眼 | 2024年 |
| 7 | PCサングラス | 2024年 |
| 9 | 調光老眼 | 2024年 |
| 11 | 既成近眼 | 2024年 |
| 21 | 老眼 | 2025・2026年 |
| 23 | PCサングラス | 2025・2026年 |
| 25 | 調光老眼 | 2025・2026年 |
| 27 | 既成近眼 | 2025・2026年 |

現行主シートでは月別必要数も数式と固定値が混在する。年間販売想定数を持つ18品番の5,820個のSKU・月セルのうち、数式は2,936セル、固定値は2,884セルである。

### 5.5 入荷予定

入荷予定は月別必要数の右隣へSKU単位で手入力する。値がない月も0または空欄で管理されている。

例:

```text
品番 fisi-05
7月 1,210枚
8月   600枚
11月  600枚
```

現行ブックでは、発注番号、発注日、発注残、予定入荷日、確定／未確定、遅延、キャンセル、仕入先、リードタイム等は構造化されていない。注記とセル値で管理される。

### 5.6 将来残数

初月と翌月以降の基本式は次のとおりである。

```excel
初月残数 = フリー在庫 + EC合計 - 当月必要数 + 当月入荷予定数
翌月残数 = 前月残数 - 当月必要数 + 当月入荷予定数
```

実例:

```excel
AI7 = SUM(J7:K7) - CI7 + CJ7
    = (3 + 35) - 10.228310... + 20
    = 47.771689...

AJ7 = AI7 - CK7 + CL7
```

将来残数の列対応は次のとおりである。

| 残数列 | 月 | 必要数 | 入荷予定 |
|---|---|---|---|
| AI | 2026-07 | CI | CJ |
| AJ | 2026-08 | CK | CL |
| AK | 2026-09 | CM | CN |
| AL | 2026-10 | CO | CP |
| AM | 2026-11 | CQ | CR |
| AN | 2026-12 | CS | CT |
| AO | 2027-01 | CU | CV |
| AP | 2027-02 | CW | CX |
| AQ | 2027-03 | CY | CZ |

現行レイアウトの将来残数は9か月であり、4月～6月を含む12か月計算になっていない。

また、将来残数セル1,746個のうち数式は110セル、固定値は1,636セルである。前提更新時の自動再計算性は低い。

### 5.7 欠品表示

`AI:AQ` の明細範囲には条件付き書式が設定されている。


### 5.8 合計行

294行目に品番合計がある。年間販売数F294の式は20個の品番ヘッダー行を個別に加算している。

```excel
=F6+F38+F65+F116+F127+F27+F138+F76+F89+F155
 +F99+F49+F164+F171+F182+F195+F211+F112+F281+F271
```

この20件は「優先順位1～18＋23～24」であり、「優先順位1～20」ではない。優先順位16、17、19～22は年間値が0または空欄であるため、保存値上の合計は全24枠の非ゼロ値合計と一致しているが、行追加・順位変更に弱い式である。

月別合計の `AS294:CH294` には、削除済み行を指す参照が残り、42セルすべてが `#REF!` となっている。`CI294:CZ294` は保存時点では計算値を保持している。

## 6. 売上上位品番の選定仕様

### 6.1 `差し替え品番`

品番選定は金額順を基本に、時期別に手動で差し替える。

| 列 | 内容 |
|---|---|
| B | 優先順位 |
| C | 2024年9月までの対象品番 |
| D | 2024年10月以降の対象品番 |
| E | 2026年8月以降の対象品番 |
| F | 2026年の参考数値 |
| G:I | 2025年7月時点の年間販売想定数の改修前後 |
| J | 手動調整理由 |

手動調整理由には、Amazon販売増、前年120～130%、欠品なしを仮定した転換率、当期販売の伸び等が記載されている。ただし、その根拠データと計算式はセルから追跡できない。

2026年8月以降の先頭品番は `si-05` だが、主シートの優先順位1は `fisi-05` のままである。差し替えが未反映なのか、意図的な継続なのかは確認が必要である。

### 6.2 `2026売上ランキング 1-5`

左側に2026年1～5月の売上実績、右側に販売試算表の年間売上予測ランキングを持つ。

- 実績側は品番、売上数、返品数、売上金額、返品額、純売上、原価、粗利を保持する。
- 予測側は品番、月数、月商、年数、年商を保持する。
- ランキング表には計算式がなく、値貼り付けである。
- 主シートおよび `差し替え品番` との参照式はない。

### 6.3 上位20判定の実態

現行ブックには、売上データから上位20品番を自動抽出する数式はない。順位・差し替え・追加確認品番を人が決め、主シートへ転記する方式である。

また、次の定義が明文化されていない。

- 売上金額、純売上、販売数量、粗利のどれで順位付けするか
- 集計対象モールと返品の扱い
- 集計期間を直近何か月にするか
- 新商品、終売品、EC専売品、代替品をどう扱うか
- 同一品番の表記揺れをどう統合するか
- 上位20外でも重要な品番を追加する条件

## 7. 補助シートの仕様

### 7.1 `月別販売比率`

4カテゴリーについて4月～翌3月の構成比を保持する。

| カテゴリー | 合計 | 特徴 |
|---|---:|---|
| 老眼 | 100.461% | 9月が12%で最大 |
| PCサングラス | 100.064% | 7月が約21.6%で最大 |
| 調光老眼 | 99.645% | 7月が18%で最大 |
| 既成近眼 | 100.172% | 12月が約10.9%で最大 |

各合計は100%と完全一致しない。このため、年間販売想定数と12か月必要数合計に最大約0.46%の差が生じる。

2024年と2025・2026年の比率は同値で、年ごとの再推計はされていない。プライムデー、プライム感謝祭、ブラックフライデー、スーパーセールの文字表示はあるが、イベント増分を加算する式はない。

### 7.2 `度数別比率`

度数構成の標準パターンを持つ。

- 5度数: 20%、30%、27%、15%、8%
- 4度数: 30%、35%、25%、10%
- +0.50を含む構成: +0.50を32%とするパターン等
- 3度数: 40%、37%、23%
- 高年齢向け4度数: 20%、35%、30%、15%

下段には商品別の販売実績と構成比がある。ただし主シートはこの標準比率を参照しておらず、基準年のF列構成または固定値を使う。

シート自身にも「在庫切れ影響により正確な販売数量割振が未定」と記載されており、現行ロジックの弱点を認識している。

### 7.3 `【旧】販売試算表`

旧版は4月～翌3月の12か月を明示し、各月について次の5列を持つ。

```text
必要数 / 在庫確保 / 入荷品確保 / 確保数計 / 差
```

旧版の品番合計必要数は基本的に `年間販売想定数÷12` で均等配分し、明細では月別比率を参照する。月ごとの在庫確保が同じ初期在庫を繰り返し参照する箇所があり、月次の連続した在庫推移とは異なる。

現行主シートは連続残数式へ移行しているが、表示期間が9か月へ短縮され、数式の多くが固定値化している。

### 7.4 `FL-3000在庫`

FL-3000をカラー・度数別に分け、フリー在庫、EC在庫、7月・10月等の入荷確保数を手入力する。主シート上部に確認指示があるが、主シートとの数式連携はない。

## 8. 数式・データ品質上の確認事項

### 8.1 現行主シートの実在エラー

- `AS294:CH294` の42セルが `#REF!`。
- 合計式が削除済み品番行を個別加算していることが原因。
- 明細の欠品判定には直接使われないが、全体必要数・入荷数の月別集計は利用できない。

### 8.2 旧 `在庫推移` の実在エラー

- 保存済み `#REF!` が217セルある。
- 削除・移動された行を参照する将来残数式が主因。
- 現行システム仕様の根拠にはせず、参考版として隔離すべきである。

### 8.3 参照先の誤記

`在庫推移 (2026.08～)!BA98` は次の式を持つ。

```excel
=$H$98*月別販売比率!BA425
```

`月別販売比率` の使用範囲は27行までであり、同じ品番ブロックの他セルから見ると `BA25` の誤記と考えられる。参照先が空欄のため、該当SKUの当月必要数を0として扱う可能性がある。

### 8.4 日付見出しの不整合

必要数・入荷予定の見出しは `CU` まで2027年1月へ順次進むが、`CW` と `CY` は2026年8月・9月の日付が重複している。一方、対応する残数列 `AP`、`AQ` の見出しと比率参照は2027年2月・3月である。

したがって、`CW`、`CY` の日付表示はそれぞれ2027年2月、2027年3月の誤記である可能性が高い。

### 8.5 数式と固定値の混在

| 対象 | 数式セル | 固定値セル | 評価 |
|---|---:|---:|---|
| SKU年間販売想定数 | 52 | 142 | 品番前提変更が大半のSKUへ伝播しない |
| 月別必要数 | 2,936 | 2,884 | 約半数が再計算されない |
| 9か月将来残数 | 110 | 1,636 | ほぼ固定値で、入荷変更時の追従性が低い |

この混在は、試算しても欠品が頻発する原因候補の一つである。入力を変更したつもりでも、下流の固定値が以前の計算結果を保持する可能性がある。

### 8.6 数量の端数

月別必要数は小数のまま計算される。商品は枚数・個数単位であるため、発注用途では少なくともSKU単位で切り上げ、さらに発注ロット・ケース入数・最小発注数へ丸める必要がある。

## 9. 現行試算方法の妥当性評価

| 観点 | 現行対応 | 評価 | 主な問題 |
|---|---|---|---|
| 需要予測 | 年間販売想定数を手動設定 | 不十分 | 再現可能な計算根拠、予測誤差、バックテストがない |
| 販売ペース算出期間 | 2024年ベース表記、2026年1～5月ランキング、手動調整が混在 | 不明確 | 直近3・6・12か月、前年同月等の優先順位が定義されていない |
| 欠品補正 | 一部品番で人手調整 | 不十分 | 欠品日数を使う共通式がなく、実績の過小評価が残る |
| 季節性 | 4カテゴリーの月別比率 | 一部妥当 | 商品別・モール別ではなく、毎年同じ。合計も100%と一致しない |
| 販促・イベント | イベント名の表示のみ | 未対応 | セール増分、広告、価格変更を数値化していない |
| 安全在庫 | なし | 未対応 | 需要変動と供給変動への余裕がない |
| リードタイム | `fisi-05` の「2か月前」等の注記 | 未対応 | 品番・仕入先別の計算項目がない |
| 入荷予定 | SKU・月別手入力 | 一部妥当 | 発注残・確定度・ETA・遅延が構造化されていない |
| 将来在庫 | 初期在庫－需要＋入荷 | 基本式は妥当 | 負在庫を持ち越し、固定値が多く、現在は9か月のみ |
| 必要在庫 | 月別必要数と残数を目視 | 未対応 | 必要在庫・不足数・推奨発注数の独立式がない |
| 上位20判定 | 人手で選定・差し替え | 不十分 | 定義、抽出、更新、例外ルールが自動化されていない |
| 4か月欠品判定 | 色付きセルを目視 | 不十分 | 品番単位の自動判定・アラートがない |
| 12か月推移 | 旧版には存在、現行は9か月 | 要改善 | システム要件と現行表示が一致しない |

### 9.1 欠品による販売実績の過小評価

現行式は基準年間販売数FのSKU構成比を将来へ引き伸ばす。

```text
欠品したSKU
→ 実績販売数が本来需要より少なくなる
→ 将来年間販売想定数のSKU配分も少なくなる
→ 月別必要数が少なくなる
→ 発注数も少なくなる
→ 再び欠品する
```

`月別販売比率` と `度数別比率` の注記からも、この問題は現場で認識されている。ただし、現行ブックには欠品日数、販売可能日数、機会損失数量を入力・補正する仕組みがない。

### 9.2 現行ロジックを使える範囲

次の条件を満たす場合、現行ロジックは短期の欠品候補抽出の参考値として使える。

- 年間販売想定数を担当者が商品ごとに妥当性確認する。
- SKU別現在庫と入荷予定が最新である。
- 固定値領域を毎回再計算・再貼付する。
- 欠品セルを「警告」として扱い、発注数の最終決定には使わない。

必要在庫の自動算出、発注自動化、昨対割れ原因の定量検証に使うには、改善ロジックが必要である。

## 10. システム化で保持すべき現行仕様

次の考え方はMall Insightへ引き継ぐ価値がある。

1. 品番→カラー→度数の階層管理。
2. Amazon、楽天、Yahoo!、au PAY、ECストック、フリー在庫の統合表示。
3. 年間予測を月別季節性へ配分する考え方。
4. SKU・月別の入荷予定。
5. 月次の将来在庫推移。
6. 欠品候補の色分け。
7. 上位品番、追加確認品番、除外品番の区分。
8. 調整理由・前提変更履歴の保存。
9. 現行Excelと同じ結果を出す再現モード。

## 11. システム化で改善すべき計算仕様

### 11.1 需要実績の欠品補正

最低限、日次または時間帯別に次を保持する。

- 販売数量
- 販売可能在庫
- 欠品開始・終了日時
- モール別の掲載状態
- 価格、クーポン、広告、セール期間

簡易補正式:

```text
販売可能日当たり需要 = 販売数量 ÷ 販売可能日数
欠品補正月間需要 = 販売可能日当たり需要 × 月の日数
推定機会損失 = 欠品補正月間需要 - 実販売数量
```

在庫が極端に少ない期間は転換率が歪む可能性があるため、「在庫あり／在庫僅少／欠品」を分ける。

### 11.2 販売ペース

品番・SKUごとに複数候補を算出し、予測精度で選択する。

- 直近28日販売可能日平均
- 直近3か月移動平均
- 直近6か月移動平均
- 直近12か月平均
- 前年同月
- 前年同月×直近成長率
- セール・広告影響を除いた平常需要

採用モデル、採用期間、予測作成日時、手動上書き、上書き理由を履歴化する。

### 11.3 季節性

```text
月別需要 = 基準需要 × 正規化済み季節指数 × 販促係数 × 価格係数
```

- 季節指数の12か月合計は必ず12、または構成比合計を100%へ正規化する。
- 商品別データが少ない場合はカテゴリー比率を使い、データ蓄積後に商品別へ移行する。
- Amazon、楽天、Yahoo!、au PAYで季節性が異なる場合はモール別に持つ。

### 11.4 安全在庫と発注点

固定リードタイムの簡易式:

```text
安全在庫 = サービス係数Z × 日次需要の標準偏差 × √リードタイム日数
発注点 = リードタイム中の予測需要 + 安全在庫
```

リードタイム変動を含む場合:

```text
安全在庫 = Z × √(平均LT × 需要分散 + 平均需要² × LT分散)
```

サービス係数は欠品許容度で設定する。例として95%なら約1.65だが、実際の値は商品重要度・粗利・欠品コストで決める。

### 11.5 将来在庫と機会損失

実在庫と不足を分離する。

```text
販売可能数 = MIN(月初在庫 + 確定入荷, 予測需要)
月末在庫 = MAX(0, 月初在庫 + 確定入荷 - 予測需要)
推定失注数 = MAX(0, 予測需要 - 月初在庫 - 確定入荷)
```

バックオーダーを受け付ける商品だけ、別途バックオーダー残を持つ。

### 11.6 必要在庫・推奨発注数

4か月先まで欠品させない場合の基本式:

```text
必要在庫 = 対象期間の累計予測需要 + 期末安全在庫
不足数 = MAX(0, 必要在庫 - 現在利用可能在庫 - 対象期間内の確定入荷)
推奨発注数 = 発注ロット・最小発注数へ切り上げた不足数
```

入荷が月途中の場合は月次ではなく日次で計算する。販売開始前の新商品は類似商品の実績、初回投入計画、予約・閲覧・転換率等を使う。

### 11.7 上位20と4か月欠品判定

推奨仕様:

```text
1. 基準日時点で品番別の順位指標を計算
2. 除外条件を適用
3. 上位20件を確定
4. 手動追加・手動除外を理由付きで適用
5. 現在月を含む4か月の在庫推移を計算
6. 月末在庫 < 安全在庫 または 推定失注数 > 0 なら要対応
```

順位指標は少なくとも次から選択可能にする。

- 純売上金額
- 販売数量
- 粗利額
- 欠品機会損失を加えた推定需要金額

画面には、順位根拠、欠品予測日、最小予測在庫、不足数、次回入荷日、推奨発注数を表示する。

### 11.8 12か月推移

現行の9か月固定列を廃止し、基準月から11か月後までを動的生成する。

```text
基準月 + 0～11か月
```

過去の試算を再現できるよう、試算バージョンごとに基準日、前提、予測値、在庫、入荷予定を保存する。

## 14. 受入テスト例

### 14.1 現行再現テスト

`fisi-05` の例:

```text
基準年間販売数 = 1,314
年間販売想定数 = 3,500
SKU基準販売数 = 48
SKU年間予測 = 48 × 3,500 ÷ 1,314 = 127.853881...
2026年7月需要 = 127.853881... × 8% = 10.228310...
初期在庫 = フリー3 + EC35 = 38
2026年7月入荷 = 20
2026年7月末残数 = 38 - 10.228310... + 20 = 47.771689...
```

システムの現行再現モードはこの結果と一致すること。

### 14.2 改善モードのテスト

- 欠品10日を入力すると、販売可能日ベースの需要へ補正される。
- 月別比率の合計が100%へ正規化される。
- 入荷予定日を遅らせると、欠品予測日と不足数が自動更新される。
- 安全在庫を増やすと、推奨発注数が増える。
- 予測残数は0未満にならず、未充足需要が失注数へ計上される。
- 基準月を変更すると、12か月の列が自動で切り替わる。
- 上位20の順位指標を変更すると、対象品番が自動再選定される。

## 15. システム化前に確定すべき業務ルール

1. 「売上上位20」の順位指標は純売上、販売数量、粗利のどれか。
2. 上位20の集計期間は直近何か月か、前年同期を含むか。
3. 4か月後の意味は「4か月目の月末」か「今日から120日」か。
4. 欠品判定は在庫0、在庫1未満、安全在庫未満のどれか。
5. フリー在庫を全量販売可能とみなすか、他チャネル用引当を差し引くか。
6. 入荷予定のうち、発注済み・生産中・未発注をどう計算へ含めるか。
7. 商品・仕入先別の標準リードタイムとばらつき。
8. 目標サービス水準と安全在庫方針。
9. 欠品中の需要補正方法。
10. 新商品、終売、仕様替え、後継品、セット品の扱い。
11. SKU単位の発注ロット、ケース入数、最小発注数。
12. 需要予測を手動上書きできる権限と承認フロー。

## 16. 推奨移行順序

1. 品番・SKU・モールSKUの統合マスタを作る。
2. 日次販売、日次在庫、欠品履歴、入荷予定を自動収集する。
3. 現行Excel再現ロジックを実装し、代表品番で照合する。
4. 上位20と4か月欠品判定を自動化する。
5. 12か月在庫推移を実装する。
6. 欠品補正と機会損失推計を追加する。
7. 安全在庫、リードタイム、推奨発注数を追加する。
8. 予測誤差を毎月検証し、商品別に採用モデルを改善する。
