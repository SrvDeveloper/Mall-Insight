# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## リポジトリの性質

コードのないドキュメントリポジトリである。ECモール統合分析システム「Mall Insight」（SKU別の需要予測と12か月在庫試算）の設計文書のみを管理する。ビルド、テスト、リントのコマンドは存在せず、成果物はすべて UTF-8 の Markdown である。

リポジトリのルートは Obsidian の vault でもある。`.obsidian/` 配下の設定・テーマ・プラグインも Git 管理下にあるが、設計上の意味は持たない。

作業は Markdown の読み書きと `git` のみで完結する。

このシステムの設計・開発は担当者ひとりで行っている。複数人での合意形成や引き継ぎを前提とした網羅的な文書は作らず、設計判断を後から追える最小限の記述にとどめる。そのため各設計書の分量は意図的に抑えており、書き足す際も文書を膨張させない。

## Obsidian 環境

- `.obsidian/workspace.json` は Obsidian を開くたびに書き換わる。差分に現れても要件の変更ではない。要件の変更をコミットするときは、パスを明示してステージし、この種の設定ファイルを巻き込まない。
- obsidian-git プラグインが入っている。Obsidian 側から別途コミットされたり、編集中に作業ツリーが変わったりすることがあるため、編集前に `git status` で現在の状態を確認する。
- 文書間のリンクは Obsidian の `[[ウィキリンク]]` ではなく、標準 Markdown の相対リンク（例: `[販売実績保存データ](販売実績保存データ.md)`）で書く。既存文書がこの形式で統一されている。

## 文書間の依存関係

## 設計上の中核原則

文書全体を貫く判断であり、個別記述を変更するときも崩さない。

1. **「実績」「年間販売目標」「システム需要予測」を別データとして保持する。** 在庫推移はシステム需要予測による推移を基本とし、年間販売目標による推移（販売試算）は切り替えて確認する参考の推移とする。年間販売目標（担当者の手入力）はシステム需要予測の計算に使わない。目標達成率と予測精度は別指標として扱う（`プロダクト/03.決定記録.md` K-048）。
2. **現行再現モードと改善モードの二段構え。** 移行照合用に現行 Excel と同じ計算（負在庫の持ち越し、比率合計が100%でない月別比率、小数保持）を再現するモードを持つ。本番の改善モードでは実在庫を0未満にせず、未充足需要を別途保持する。両モードの規則を混ぜない。
3. **欠品を補正しない実績を需要とみなさない。** 平均日販は販売可能日数（欠品日・販売停止日を除外）で除算する。補正しても元の販売実績は変更せず、補正前後の両方を保持する。
4. **予測値には版と根拠を持たせる。** 予測バージョン、モデルバージョン、使用データ、計算式および算出日時を確認できるようにする。在庫試算は履歴を保存せず、最新データから都度算出する。バックテストでは予測時点より後の実績を使わない。
5. **欠損を0として黙って処理しない。** 参照欠損・鮮度超過・季節係数合計の不整合は警告する。

### 主要な計算式

要件定義書に記載済みの式。新しい式を書くときはこれらと整合させる。

```text
平均日販     = 対象期間販売数 ÷ 販売可能日数
月末在庫     = MAX(0, 月初在庫 + 確定入荷数 - システム需要予測)
未充足需要   = MAX(0, システム需要予測 - 月初在庫 - 確定入荷数)
安全在庫     = 平均日販 × 安全在庫日数
推奨発注数   = MAX(0, 予測期間需要 + 安全在庫 - 現在庫 - 発注済数量)
欠品警告条件 = 在庫日数 < 調達リードタイム + 安全在庫日数
```

丸めの規則: 途中値は小数精度を保持し表示時に丸める。発注数量は最終段階でのみ発注ロット・最小発注数へ切り上げる。年間値をSKU・月別へ配分した場合、丸め後の合計を元の年間値に一致させる。

## 執筆規約

既存文書に合わせる。

- 日本語、である調。一人称・呼びかけを使わない。
- 章は `## 1. 見出し`、節は `### 1.1 見出し` と番号を振る。機能要件のみ `#### FR-0xx 名称` を付ける。ID は分類ごとに10刻み（実績=001系、予測=010系、目標=020系、比較=030系、需要利用=040系、在庫=050系、試算=060系、履歴=070系）で、既存 ID の再利用・振り直しはしない。
- 一覧性のある内容は表にする。計算式は ```text フェンスで囲む。
- 用語は「用語定義」（`要件定義書.md` 5章）の語を使う。特に「年間販売目標」と「システム需要予測」を混同しない。現行 Excel の「年間販売想定数」は年間販売目標に統合した（K-048）。
- 日付は絶対表記とする。文書内で表記を混在させない。
- 文書冒頭のメタ情報は文書によって形式が異なる。`要件定義書.md` は「## 1. 文書情報」の表、`documents/取込要件/` 配下は見出し直下の箇条書き（文書状態・更新日・対象システム等）である。改訂したら、その文書の既存形式のまま版数・更新日・ステータスを更新する。
- 1文書が膨大にならないようにする。既存文書にある内容は繰り返さず相対リンクで参照する。加筆で分量が増えたときは、圧縮するか `documents/取込要件/` のように主題ごとの文書へ分割する。
