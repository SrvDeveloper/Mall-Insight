# Amazon全注文レポート取込要件

- 文書状態：確定版
- 更新日：2026年8月31日
- 対象システム：販売実績管理システム
- 実データ検証状況：全注文レポート（注文日基準）確認済み、全注文レポート（最終更新日基準）確認済み

本書は、Amazon Seller Centralの全注文レポートに固有の取込要件を定める。  
全取込元に共通する方針は[販売実績取込要件](01.販売実績取込要件.md)に、保存項目の全体像と共通の保存形式は[04.販売実績保存データ](04.販売実績保存データ.md)に定める。  
章構成は[BOSS受注実績取込要件](02.BOSS受注実績取込要件.md)と共通であり、その定義は[販売実績取込要件 第4.5節](01.販売実績取込要件.md)による。  
用途に応じたレポート基準（注文日基準・最終更新日基準）の使い分けは[取込処理・運用要件 第2章](05.取込処理・運用要件.md)に定める。

## 1. 入力ファイル

| 項目 | 内容 |
|---|---|
| 取得元 | Amazon Seller Centralの全注文レポート |
| ファイル形式 | テキストファイル |
| 区切り文字 | タブ |
| 文字コード | UTF-8またはShift_JIS（CP932） |
| 項目名 | 1行目 |
| データ構造 | 1注文明細につき1行 |

文字コードは、BOMおよびUTF-8としての妥当性を確認して判定し、UTF-8でない場合はShift_JIS（CP932）として読み込む。

## 2. 必須列・値の扱い

Amazonファイルには、最低限次の列が必要である。  
ここでの必須とは列の存在を意味し、各行の値が空欄であることを一律に取込エラーとするものではない。

| 列名 | 用途 | 値の必須 |
|---|---|---|
| `amazon-order-id` | 注文の一意キーおよびモール注文番号 | 必須 |
| `purchase-date` | 販売日時 | 必須 |
| `last-updated-date` | 取込対象期間の判定 | 必須 |
| `order-status` | 販売計上状態の判定 | 必須 |
| `sales-channel` | マルチチャネル出荷注文の判定 | 空欄を許容 |
| `order-item-id` | 注文明細の一意キー | 必須 |
| `fulfillment-channel` | 出荷倉庫の判定 | 必須 |
| `item-status` | 明細状態の検証 | 必須 |
| `asin` | 取込元商品ID | 必須 |
| `sku` | 取込元SKU。商品コード解決には使用しない | 必須 |
| `product-name` | 商品名 | 必須 |
| `quantity` | 販売数量 | 必須 |
| `item-price` | 明細の商品金額 | 必須 |
| `item-tax` | 明細の税額 | 空欄を許容 |

すべての列名は前後の空白を除去してから必須列と照合する。  
Seller Centralから取得したファイルでは、`order-item-id`の列名の末尾に半角空白が付与される場合があるため、前後空白の除去を必須とする。

`order-status`が`Shipped`の明細では、上表で値を必須とした列に値が存在することを要する。  
ただし、第3章によりマルチチャネル出荷注文として取込対象外とした行は、この必須値検証の対象としない。  
空欄を許容する列の金額計算上の扱いは第10章に定める。  
値の必須条件を満たさない行の扱いは[取込エラー・警告 第2章](06.取込エラー・警告.md)に定める。  
`last-updated-date`の保存および取込元データの新旧判定は未定義である。

## 3. 取込対象

`sales-channel`が`Non-Amazon`の行は、Amazon以外の販売チャネルで受注した注文をFBA在庫から出荷したマルチチャネル出荷であり、Amazonでの販売ではない。  
このため、`order-status`および`item-status`の値にかかわらず販売実績の取込対象外とする。  
取込対象外としたマルチチャネル出荷注文は、次のとおり扱う。

- 販売注文および販売注文明細を新規登録せず、保存済みデータの更新および販売計上状態の変更も行わない（[販売実績保存データ 第8章](04.販売実績保存データ.md)）。
- 第2章の必須値検証および[取込エラー・警告 第2章](06.取込エラー・警告.md)の行単位の取込エラー判定の対象としない。`item-price`等の金額列が空欄であっても取込エラーとしない。
- 取込エラーおよび警告としては記録せず、取込履歴のマルチチャネル出荷除外件数として記録する（[販売実績保存データ 第5章](04.販売実績保存データ.md)）。

判定は`sales-channel`の値が`Non-Amazon`と一致するかどうかだけで行い、`amazon-order-id`の形式および金額列の空欄は判定に使用しない。  
`sales-channel`が空欄、または`Amazon.co.jp`および`Non-Amazon`以外の値である場合は、マルチチャネル出荷と判定せず取込対象としたうえで、確認用の警告を記録する（[取込エラー・警告 第3章](06.取込エラー・警告.md)）。  
`sales-channel`は取込対象の判定にだけ使用し、保存しない。

上記により取込対象外としなかった注文明細のうち、`order-status`が`Shipped`の注文明細だけを販売実績として取り込む。

次のステータスは販売実績に含めない。

- Pending
- Unshipped
- Partially Shipped
- Cancelled

`item-status`は明細状態の検証にだけ使用する。`order-status`が`Shipped`であっても、  
想定外の`item-status`が設定されている場合は警告を記録する。

BOSSと異なり、対象外ステータスの行も入力ファイルに含まれる。  
対象外ステータスの行は新規登録しないが、同じ注文が保存済みである場合は販売計上状態を更新する（[販売実績保存データ 第7章](04.販売実績保存データ.md)）。  
これにより、取込後に`Cancelled`へ変化した注文は、自動で販売実績から除外される。  
一方、出荷後の返品および返金は全注文レポートから取得できないため、手動で販売実績へ反映する（[販売実績取込要件 第4.4節](01.販売実績取込要件.md)、[販売実績保存データ 第11章](04.販売実績保存データ.md)）。

## 4. 販売日

`purchase-date`を販売日時として使用する。  
`purchase-date`は、次のようなタイムゾーン付きISO 8601形式で出力される。

```text
2026-08-26T14:29:25+09:00
```

販売日は、`purchase-date`を日本時間へ変換した後の日付部分とする。オフセットを無視して日付を切り出してはならない。

## 5. モール区分

Amazon全注文レポートは全行がAmazonの販売実績であるため、BOSSの`ショップID`に相当するモール区分の判定列は存在しない。  
モールコードには`AMAZON`を固定で設定する。

| 判定元 | モール |
|---|---|
| 判定列なし（ファイル種別で確定） | Amazon |

`sales-channel`は販売チャネルを表す列であり、モール区分の判定には使用しない。  
`sales-channel`が`Non-Amazon`となるマルチチャネル出荷注文は、第3章により取込対象外とする。

## 6. 出荷倉庫

FBAと自社出荷を別々の販売実績ファイルとして管理せず、全注文レポートからまとめて取り込む。  
全注文レポートの`fulfillment-channel`を、販売注文明細の出荷倉庫へ変換して保持する。

| `fulfillment-channel`の値 | 保存する出荷倉庫 |
|---|---|
| Amazon、AMAZON、AFN | `FBA` |
| Merchant、MERCHANT、MFN | `Amazon自社倉庫` |

Seller Centralの全注文レポートでは`Amazon`と`Merchant`を使用する。  
上表に存在しない値は出荷倉庫を判定できないため、行単位の取込エラーとする。

Amazonの自社出荷は`自社倉庫`ではなく`Amazon自社倉庫`として保存する。BOSS経由の自社出荷分と同一の値になることを避けるためである（[販売実績保存データ 第4.1節](04.販売実績保存データ.md)）。

## 7. 注文・明細の一意キー

注文キーには `amazon-order-id` を使用する。  
注文明細キーには、次の組み合わせを使用する。

```text
amazon-order-id + order-item-id
```

`amazon-order-id`は注文単位のキー、`order-item-id`はAmazonが付与する注文明細識別子として扱い、数値型へ変換せず文字列として保存する。

同一注文内に同一 `order-item-id` が複数行存在することは通常想定しない。  
複数行存在した場合は、ファイル内で最初に出現した1行だけを取込対象とし、  
2行目以降は行単位の取込エラーとして記録し、登録しない。

重複明細を取込エラーとして扱う点はBOSSと異なる。BOSSでは2行目以降を警告として取込対象外にする（[BOSS受注実績取込要件 第7章](02.BOSS受注実績取込要件.md)）。

## 8. 注文単位で保持する項目

次の項目は注文単位の情報として保持する。

- 取込元注文ID：`amazon-order-id`
- モールコード：`AMAZON`固定
- モール注文番号：`amazon-order-id`
- 販売日時：`purchase-date`
- 商品金額合計：同一注文の取込対象明細の`item-price`合計
- 税額合計：同一注文の取込対象明細の`item-tax`合計。空欄は`0`
- 取込元注文ステータス：`order-status`

BOSSと異なり、全注文レポートには注文単位の合計金額列が存在しない。  
そのため注文単位の合計は取込対象明細から算出し、[BOSS受注実績取込要件 第10章](02.BOSS受注実績取込要件.md)に相当する注文合計と明細合計の突合は行わない。

同一注文の明細間で`purchase-date`が一致しない場合は、該当注文の販売注文および販売注文明細を登録・更新せず、注文単位の取込エラーとする（[販売実績保存データ 第3章](04.販売実績保存データ.md)）。

## 9. 注文明細単位で保持する項目

次の項目は注文明細単位の情報として保持する。

- 取込元明細ID：`order-item-id`
- 取込元商品ID：`asin`
- 取込元SKU：`sku`
- 商品名：`product-name`
- 販売数量：`quantity`
- 商品単価：`quantity`が1以上の場合は`item-price ÷ quantity`
- 商品金額：`item-price`
- 税額：`item-tax`。空欄は`0`
- 出荷倉庫：`fulfillment-channel`を変換した値（第6章）
- 取込元注文ステータス：`order-status`
- 取込元明細ステータス：`item-status`

`item-price`および`item-tax`は、単価ではなく数量分を合計した明細金額である。  
商品1点当たりの金額を保持するBOSSとは、金額列の単位が異なる（[BOSS受注実績取込要件 第9章](02.BOSS受注実績取込要件.md)）。  
商品単価は取込元に存在しないため、`quantity`が1以上の明細について`item-price ÷ quantity`で算出する。

`asin`はAmazonが商品に付与する識別子であり、出品者が設定する`sku`とは別の項目として文字列で保存する。  
BOSSが`商品ID`を取込元商品IDとして保持するのと同じ位置づけであり、いずれの取込元でも取込元商品IDを`NULL`にしない（[販売実績保存データ 第4章](04.販売実績保存データ.md)）。

`asin`は子ASINとしてSKUマスタを参照し、システム内商品コードを特定する。`sku`は出品者が変更できるため、商品コード解決には使用せず、取込時点の表示値および履歴情報として保存する。同一`asin`に異なる`sku`が現れても、同一商品として扱う（[販売実績取込要件 第5章](01.販売実績取込要件.md)）。

## 10. 金額の扱い

Amazonでは注文単位の合計金額列がないため、明細金額を正本として管理し、注文単位の合計は明細から算出する（第8章）。

- 注文明細の商品金額：`item-price`
- 税額：`item-tax`。空欄の場合は`0`として扱う

`item-price`は、単価ではなく数量分を合計した明細金額として保存する。  
BOSSの`税込別`に相当する税区分の列は存在しないため、`item-price`の税区分による換算は行わない。

単価が必要な場合は、`quantity`が1以上の明細について次のとおり算出する。`quantity`が0の明細では単価を算出しない。

```text
商品単価 = item-price ÷ quantity
```

取り扱う金額はすべて日本円とする。`currency`列がファイルに含まれていても取込判定や金額変換には使用せず、保存しない。外貨および通貨換算は対象外とする。  
`shipping-price`、`shipping-tax`、`ship-promotion-discount`、`promotion-ids`、`gift-wrap-price`および`gift-wrap-tax`は取り込まず、保存しない。

## 11. 0円商品の扱い

`item-price`が0円の明細を許可する。  
プロモーション品、同梱品などの可能性があるため、商品金額0円だけを理由に取込エラーとしない。  
0円商品を含む場合は、確認用の警告を記録する（[取込エラー・警告 第3章](06.取込エラー・警告.md)）。

## 12. 個人情報の扱い

販売実績管理に不要な購入者氏名、メールアドレス、電話番号、配送先住所などは取り込まない。

全注文レポートには、`ship-city`、`ship-state`、`ship-postal-code`、`ship-country`などの配送先関連列が含まれる場合がある。  
これらの列、および追加列や別形式のファイルに含まれる個人情報は保存対象外とする。
