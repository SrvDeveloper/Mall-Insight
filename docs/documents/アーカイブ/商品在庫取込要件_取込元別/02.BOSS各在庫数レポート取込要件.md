# BOSS各在庫数レポート取込要件

> 本書は2026年10月1日に廃止した。在庫は別システムが出力する日次在庫CSVから取り込む方式へ変更しており、現行の要件は[商品在庫取込要件](../../商品在庫取込要件/01.商品在庫取込要件.md)に定める。本書は旧取込元の調査結果として参照専用で残す。

- 文書状態：確定版
- 更新日：2026年8月31日
- 対象システム：商品在庫管理システム
- 実データ検証状況：BOSS各在庫数レポート 確認済み

本書は、BOSS各在庫数レポートに固有の取込要件を定める。`BOSS自社倉庫`および`RFC`の在庫が対象である。  
全取込元に共通する方針は[01.商品在庫取込要件](../../商品在庫取込要件/01.商品在庫取込要件.md)に、保存項目の全体像と共通の保存形式は[05.商品在庫保存データ](../../商品在庫取込要件/03.商品在庫保存データ.md)に定める。  
章構成は[03.Amazon出品詳細レポート取込要件](03.Amazon出品詳細レポート取込要件.md)および[04.Amazon FBA在庫レポート取込要件](04.AmazonFBA在庫レポート取込要件.md)と共通であり、その定義は[商品在庫取込要件 第4.6節](../../商品在庫取込要件/01.商品在庫取込要件.md)による。

## 1. 入力ファイル

| 項目 | 内容 |
|---|---|
| 取得元 | BOSS各在庫数レポート |
| ファイル形式 | CSV |
| 区切り文字 | カンマ |
| 文字コード | Shift_JIS（CP932） |
| 改行コード | CRLF |
| 項目名 | 1行目 |
| データ構造 | 1商品の1倉庫につき1行 |
| 列数 | 20列 |

文字コードを明示して読み込み、UTF-8として誤って処理しないこと。この点は[BOSS受注実績取込要件 第1章](../../販売実績取込要件/02.BOSS受注実績取込要件.md)と同一である。

1商品が複数の倉庫に行を持つため、同一商品の行が倉庫の数だけ繰り返される。実データは1530商品×2倉庫の3060行である。

## 2. 必須列・値の扱い

BOSS各在庫数レポートには、最低限次の列が必要である。  
ここでの必須とは列の存在を意味し、各行の値が空欄であることを一律に取込エラーとするものではない。

| 列名 | 用途 | 値の必須 |
|---|---|---|
| `商品ID` | 一意キーおよび取込元商品ID | 必須 |
| `SKUコード` | システム内商品コード | 必須 |
| `倉庫ID` | 倉庫区分の検証 | 必須 |
| `倉庫` | 倉庫区分の判定 | 必須 |
| `実在庫 (倉庫毎)` | 倉庫別の実在庫数 | 必須 |
| `引当済 (倉庫毎)` | 倉庫別の引当済数 | 必須 |
| `実在庫数` | 商品単位の整合性検証 | 必須 |
| `引当済 (全倉庫)` | 商品単位の整合性検証 | 必須 |
| `セット区分` | セット商品の判定 | 必須 |

すべての列名は前後の空白を除去してから必須列と照合する。  
値の必須条件を満たさない行の扱いは[取込エラー・警告 第3章](../../商品在庫取込要件/06.取込エラー・警告.md)に定める。

実データでは全3060行が20列であり、値に引用符およびカンマを含む行は存在しない。ただし解釈は引用符付きCSVとして行い、引用符で囲まれた値を許容する。

## 3. 取込対象

すべての行を在庫の取込対象とする。BOSSの受注実績と異なり、取込対象を限定するステータス列は存在しない。

第5章により倉庫区分へ変換できない行は、在庫を登録できないため行単位の取込エラーとする。

## 4. 在庫基準日

ファイルに在庫基準日を示す列は存在しない。在庫基準日は担当者が取込時に指定する（[商品在庫取込要件 第4.3節](../../商品在庫取込要件/01.商品在庫取込要件.md)、[取込処理・運用要件 第2章](../../商品在庫取込要件/05.取込処理・運用要件.md)）。

BOSS各在庫数レポートには、`実在庫数`や`引当済 (全倉庫)`の時点を示す情報が一切含まれないため、指定した在庫基準日とファイルの出力時点が一致していることは、システムでは検証できない。運用によって担保する。

## 5. 倉庫区分

`倉庫`の値により倉庫区分を判定する。

| `倉庫`の値 | 倉庫区分 |
|---|---|
| `自社倉庫` | `BOSS自社倉庫` |
| `RFC倉庫` | `RFC` |

判定には`倉庫`を使用する。[BOSS受注実績取込要件 第6章](../../販売実績取込要件/02.BOSS受注実績取込要件.md)が出荷倉庫の判定に`倉庫`を使用しており、判定元をそろえるためである。

`倉庫ID`は判定に使用せず、次の対応と一致することの検証にだけ使用する。一致しない場合は倉庫区分を`倉庫`から判定したうえで警告する。

| `倉庫ID` | `倉庫` |
|---|---|
| `61144` | `自社倉庫` |
| `999` | `RFC倉庫` |

上表に存在しない`倉庫`の値は、倉庫区分を判定できないため行単位の取込エラーとする。倉庫が追加された場合は、[商品在庫取込要件 第2章](../../商品在庫取込要件/01.商品在庫取込要件.md)の倉庫区分および倉庫マスタへ追加してから取り込む。

## 6. 商品コードの解決

`SKUコード`を変換せず、そのままシステム内商品コードとして採用する（[商品在庫取込要件 第5.2節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。Amazon取込で使用する子ASINは参照しない。

`SKUコード`がSKUマスタに存在しない場合は、商品属性未設定のSKU識別レコードとして自動登録し、警告しない（[商品在庫取込要件 第5.4節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。

## 7. 一意キー・重複行の扱い

一意キーには、次の組み合わせを使用する。

```text
商品ID + 倉庫ID
```

実データでは、次の組み合わせも一意であることを確認している。

```text
SKUコード + 倉庫
```

同一ファイル内に同一`商品ID`かつ同一`倉庫ID`の行が複数存在することは通常想定しない。  
複数行存在した場合は、ファイル内で最初に出現した1行だけを取込対象とし、2行目以降は重複行として取込対象外にし、自動的な合算は行わない。

重複行は取込エラーではなく警告として出力する。警告には、商品ID、SKUコード、倉庫区分、対象外とした行番号および重複件数を記録する。

重複行を警告として扱う点はAmazonの2文書と異なる。Amazonでは2行目以降を行単位の取込エラーとする（[Amazon出品詳細レポート取込要件 第7章](03.Amazon出品詳細レポート取込要件.md)、[Amazon FBA在庫レポート取込要件 第7章](04.AmazonFBA在庫レポート取込要件.md)）。この差は[BOSS受注実績取込要件 第7章](../../販売実績取込要件/02.BOSS受注実績取込要件.md)と同じ扱いをそろえたものである。

## 8. 保持する在庫数量項目

次の項目を在庫数へ保存する。

| 保存項目 | 取得元 |
|---|---|
| 販売可能在庫 | `実在庫 (倉庫毎)` − `引当済 (倉庫毎)` |
| 取込元SKU | `SKUコード` |
| 取込元商品ID | `商品ID` |

保存する在庫数量は販売可能在庫だけである（[商品在庫取込要件 第4.5節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。`実在庫 (倉庫毎)`および`引当済 (倉庫毎)`は、販売可能在庫の算出と第8.2節の整合性検証にだけ使用し、保存しない。

BOSS各在庫数レポートは、3つの取込元のうち唯一、倉庫別の引当済数を出力する。他の2つの取込元は引当済を除いた販売可能数量だけを出力するため、いずれの倉庫区分でも販売可能在庫の意味は一致する。

### 8.1 `販売可能数`を保存しない理由

BOSSの`販売可能数`は商品単位の値であり、次の式で算出されている。

```text
販売可能数 = 実在庫数 - 引当済 (全倉庫) - 安全在庫数
```

実データ1530商品のうち1528商品は`安全在庫数`が`0`であるため、`実在庫数 - 引当済 (全倉庫)`と一致する。`安全在庫数`が`1`である2商品（`spc-006-2-15`、`fll-3004-1-10`）では、`販売可能数`が`実在庫数 - 引当済 (全倉庫)`より1だけ小さい。

この定義は[要件定義書 FR-050](../../要件定義書.md)の販売可能在庫の定義と異なる。また、BOSSの`安全在庫数`はBOSS側で設定された値であり、[要件定義書 FR-062](../../要件定義書.md)でシステムが平均日販から算出する安全在庫とは別の概念である。両者を混同しないため、`販売可能数`は保存せず、販売可能在庫は倉庫別の`実在庫 (倉庫毎)`と`引当済 (倉庫毎)`から算出する。

### 8.2 商品単位の整合性検証

商品単位の合計列は複数の行に同じ値が繰り返されるため、倉庫別のレコードに重複保存しない。ただし、取込時に次の整合性を検証する。

```text
実在庫数 = 同一商品IDの実在庫 (倉庫毎) の合計
引当済 (全倉庫) = 同一商品IDの引当済 (倉庫毎) の合計
```

実データでは、1530商品すべてで両式の一致を確認している。  
一致しない場合は、該当商品の全倉庫区分の在庫数を登録・更新せず、商品単位の取込エラーとして記録する。該当しない他の商品は取込処理を継続する。

## 9. 取り込まない項目

次の列は保存しない。

| 列名 | 取り込まない理由 |
|---|---|
| `倉庫毎の実在庫`（第1列） | 第14列`実在庫 (倉庫毎)`と全3060行で同値の重複列である。列名が紛らわしいため、第14列を採用する |
| `商品名` | 商品名として信頼できない。実データ3060行のうち2866行は`SKUコード`と同値、194行は`as-ds01-1RED`のような社内管理上の別名である。商品名はSKUマスタで管理する |
| `カテゴリー名` | カテゴリーはSKUマスタおよび商品で管理する |
| `販売可能数` | 第8.1節のとおり定義が異なる。整合性検証にも使用しない |
| `実在庫 (倉庫毎)`、`引当済 (倉庫毎)` | 第8章のとおり販売可能在庫の算出にだけ使用する。実在庫数および引当済数は保存しない |
| `実在庫数`、`引当済 (全倉庫)` | 第8.2節の整合性検証にだけ使用する |
| `安全在庫数`、`安全在庫設定値` | BOSS側の設定値であり、システムが算出する安全在庫（FR-062）と別概念である。実データでは3060行中3056行が`0`である |
| `在庫しきい値` | 用途が確定していない。実データの値は`0`、`1`、`2`、`3`である |
| `未引当` | 意味を確定できない。実データでは全3060行が`0`であり、`実在庫数 - 引当済 (全倉庫) - 安全在庫数`と一致しない商品が822件ある |
| `セット構成品商品ID`、`セット構成品名`、`構成品数` | 第11章のとおりセット商品を初期対象外とする。実データでは全行空欄である |

## 10. 0在庫・マイナス在庫の扱い

- 販売可能在庫が`0`となる行も在庫0として登録する。行を省略しない。在庫が0であることと、在庫のレコードが存在しないことは区別する。
- `実在庫 (倉庫毎)`または`引当済 (倉庫毎)`が負値の場合は、`0`へ補正せず算出した販売可能在庫をそのまま登録し、警告を記録する。実データに負値は存在しない。
- `引当済 (倉庫毎)`が`実在庫 (倉庫毎)`を超える場合は、販売可能在庫が負値となる。`0`へ補正せずそのまま登録し、警告を記録する。

在庫試算で在庫を0未満にしない規則（[要件定義書 FR-060](../../要件定義書.md)）は将来在庫の計算に対する規則であり、取り込んだ実績値には適用しない。

## 11. セット商品の扱い

`セット区分`が`0`以外の行は、セット商品を表すものと考えられる。ただし実データでは全3060行の`セット区分`が`0`であり、`セット構成品商品ID`、`セット構成品名`および`構成品数`は全行が空欄であるため、セット商品の出力形式を実データで裏付けできない。

このため初期リリースでは、セット商品の構成品在庫への引き当てを行わない（[商品在庫取込要件 第6章](../../商品在庫取込要件/01.商品在庫取込要件.md)）。`セット区分`が`0`以外の行は、通常のSKUと同様に在庫を登録したうえで警告を記録する。

セット商品の在庫の按分規則は、実データで出力形式を確認したうえで別途定める。
