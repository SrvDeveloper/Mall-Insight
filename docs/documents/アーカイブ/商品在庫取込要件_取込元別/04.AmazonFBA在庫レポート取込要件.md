# Amazon FBA在庫レポート取込要件

> 本書は2026年10月1日に廃止した。在庫は別システムが出力する日次在庫CSVから取り込む方式へ変更しており、現行の要件は[商品在庫取込要件](../../商品在庫取込要件/01.商品在庫取込要件.md)に定める。本書は旧取込元の調査結果として参照専用で残す。

- 文書状態：確定版
- 更新日：2026年8月31日
- 対象システム：商品在庫管理システム
- 実データ検証状況：FBA在庫レポート 確認済み

本書は、Amazon Seller CentralのFBA在庫レポートに固有の取込要件を定める。`FBA`の在庫が対象である。  
全取込元に共通する方針は[01.商品在庫取込要件](../../商品在庫取込要件/01.商品在庫取込要件.md)に、保存項目の全体像と共通の保存形式は[05.商品在庫保存データ](../../商品在庫取込要件/03.商品在庫保存データ.md)に定める。  
章構成は[02.BOSS各在庫数レポート取込要件](02.BOSS各在庫数レポート取込要件.md)および[03.Amazon出品詳細レポート取込要件](03.Amazon出品詳細レポート取込要件.md)と共通であり、その定義は[商品在庫取込要件 第4.6節](../../商品在庫取込要件/01.商品在庫取込要件.md)による。

## 1. 入力ファイル

| 項目 | 内容 |
|---|---|
| 取得元 | Amazon Seller CentralのFBA在庫レポート |
| ファイル形式 | テキストファイル |
| 区切り文字 | タブ |
| 文字コード | Shift_JIS（CP932）またはUTF-8 |
| 改行コード | CRLF |
| 項目名 | 1行目 |
| データ構造 | 1出品者SKUにつき1行 |
| 列数 | 6列 |

文字コードは、BOMおよびUTF-8としての妥当性を確認して判定し、UTF-8でない場合はShift_JIS（CP932）として読み込む。判定規則は[Amazon全注文レポート取込要件 第1章](../../販売実績取込要件/03.Amazon全注文レポート取込要件.md)と同一である。

実データはShift_JIS（CP932）であり、`seller-sku`に日本語を含む行が1件存在する。ASCII文字だけのファイルとして扱わない。同じSeller Centralから取得した出品詳細レポートとは文字コードおよび改行コードが異なる（[Amazon出品詳細レポート取込要件 第1章](03.Amazon出品詳細レポート取込要件.md)）。

列名は英語である。`Quantity Available`および`Warehouse-Condition-code`のように、列名の内部に半角空白を含む列およびハイフンを含む列があるため、列名の前後の空白だけを除去し、内部の空白を除去しない。

## 2. 必須列・値の扱い

FBA在庫レポートには、最低限次の列が必要である。  
ここでの必須とは列の存在を意味し、各行の値が空欄であることを一律に取込エラーとするものではない。

| 列名 | 用途 | 値の必須 |
|---|---|---|
| `seller-sku` | 一意キーおよび取込元SKU | 必須 |
| `asin` | 取込元商品ID | 必須 |
| `Warehouse-Condition-code` | 取込対象の判定 | 必須 |
| `Quantity Available` | FBA倉庫の在庫数 | 必須 |

`fulfillment-channel-sku`および`condition-type`は取り込まないため（第9章）、必須列としない。

第3章により取込対象とした行では、上表で値を必須とした列に値が存在することを要する。  
値の必須条件を満たさない行の扱いは[取込エラー・警告 第3章](../../商品在庫取込要件/06.取込エラー・警告.md)に定める。

## 3. 取込対象

`Warehouse-Condition-code`が`SELLABLE`の行だけを`FBA`の在庫として取り込む。

`SELLABLE`以外の値の行は、販売不可在庫であり初期対象外とする（[商品在庫取込要件 第6章](../../商品在庫取込要件/01.商品在庫取込要件.md)）。在庫数を登録せず、確認用の警告を記録する。実データでは全1327行が`SELLABLE`であり、他の値は出現していない。

`Quantity Available`はFBA倉庫で出荷可能な数量であり、次を含まない。

- 未出荷注文に引き当てられた予約在庫（Reserved）
- FBA倉庫へ納品中の入庫予定在庫（Inbound）
- 販売不可在庫（Unsellable）

したがって`FBA`では出荷可能数量だけを把握でき、引当済数および入庫中の数量は把握できない。この制約は第8章の保存項目および[在庫利用要件](../../商品在庫取込要件/04.在庫利用要件.md)の欠品判定に影響する。

## 4. 在庫基準日

ファイルに在庫基準日を示す列は存在しない。在庫基準日は担当者が取込時に指定する（[商品在庫取込要件 第4.3節](../../商品在庫取込要件/01.商品在庫取込要件.md)、[取込処理・運用要件 第2章](../../商品在庫取込要件/05.取込処理・運用要件.md)）。

Seller Centralからダウンロードしたファイルの名称に出力日が含まれる場合がある（実データの元ブックでは`FBA在庫_08-27-2026`）が、ファイル名は在庫基準日の判定に使用しない。

## 5. 倉庫区分

倉庫区分を判定する列は存在しない。取込対象とした行の倉庫区分は`FBA`固定とする。

| 判定元 | 倉庫区分 |
|---|---|
| 判定列なし（ファイル種別で確定） | `FBA` |

`Warehouse-Condition-code`は在庫の状態を表す列であり、倉庫区分の判定には使用しない。FBA倉庫は複数の物流拠点で構成されるが、本ファイルは拠点別の内訳を出力しないため、`FBA`を1つの倉庫区分として扱う。

## 6. 商品コードの解決

`asin`を子ASINとしてSKUマスタを参照し、システム内商品コードを特定する（[商品在庫取込要件 第5.2節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。販売実績および出品詳細レポートと同じ子ASINを使用する。

`asin`がSKUマスタの子ASINに存在しない行は、在庫を登録せず未対応ASINとして記録し、警告する。自動登録の対象としない。

実データでは、1327件の`seller-sku`のうちBOSSの`SKUコード`と完全一致するものが43件、英字の大小を無視して一致するものが311件である。この一致件数は参考情報であり、Amazon SKUの完全一致または表記加工による対応付けは行わない。

Amazon側の在庫区分を名称に含むSKUも、取込時点の表示値としてそのまま保存する。実データでは`7003-9-ラベルなしの混合在庫`が1件存在する。基底の`7003-9`を機械的に切り出さない（[商品在庫取込要件 第5.3節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。

## 7. 一意キー・重複行の扱い

一意キーには`seller-sku`を使用する。実データでは1327件すべてが一意である。

`asin`はファイル行の一意キーには使用しない。実データでは129件のASINが複数の`seller-sku`に対応しているが、これは同一商品に複数のAmazon SKUが存在するためである。`asin`は子ASINとして商品識別に使用する。

`fulfillment-channel-sku`も一意キーに使用しない。FBA内部のSKUであり、システム内商品コードとの対応を保証できないためである。

同一ファイル内に同一`seller-sku`の行が複数存在した場合は、ファイル内で最初に出現した1行だけを取込対象とし、2行目以降は行単位の取込エラーとして記録し、登録しない。この扱いは[Amazon出品詳細レポート取込要件 第7章](03.Amazon出品詳細レポート取込要件.md)と同じであり、BOSSとは異なる（[BOSS各在庫数レポート取込要件 第7章](02.BOSS各在庫数レポート取込要件.md)）。

重複行を除外して商品コードを解決した後、同一の`asin`から同じシステム内商品コードへ解決された複数行は同一商品として扱う。各行を在庫取込明細へ保存し、`Quantity Available`を合計して`FBA`の在庫数を1件登録する。

## 8. 保持する在庫数量項目

次の項目を在庫取込明細へ保存し、商品単位に集約した販売可能在庫を在庫数へ保存する。

| 保存項目 | 取得元 |
|---|---|
| 販売可能在庫 | `Quantity Available` |
| 取込元SKU | `seller-sku` |
| 取込元商品ID | `asin` |

`Quantity Available`は予約在庫を除いた出荷可能数量である。BOSSのように実在庫数と引当済数へ分解することはできないが、保存するのは販売可能在庫だけであるため、`Quantity Available`をそのまま販売可能在庫として採用する（[商品在庫取込要件 第4.5節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。

FBA倉庫に物理的に存在する総在庫数（予約在庫および販売不可在庫を含む）は、本ファイルからは取得できない。

`asin`は、[販売実績保存データ 第4章](../../販売実績取込要件/04.販売実績保存データ.md)の取込元商品IDと同じ値であり、文字列として保存する。

## 9. 取り込まない項目

次の列は保存しない。

| 列名 | 取り込まない理由 |
|---|---|
| `fulfillment-channel-sku` | FBA内部のSKUであり、在庫管理および商品コードの解決に使用しない。実データではすべて`X`で始まる値である |
| `condition-type` | 商品コンディション別の在庫管理は初期対象外である。実データでは全1327行が`NewItem`である |

`Warehouse-Condition-code`は第3章の取込対象の判定にだけ使用し、保存しない。

## 10. 0在庫・マイナス在庫の扱い

- `Quantity Available`が`0`の行は在庫0として登録する。実データでは1327行のうち913行が`0`である。行を省略しない。
- `Quantity Available`が負値の場合は、`0`へ補正せずそのまま登録し、警告を記録する。実データに負値は存在しない。

FBA在庫レポートは在庫が0のSKUも出力するため、`0`の行を除外すると、前回取込に存在したSKUの消失として誤検知される（[商品在庫取込要件 第4.4節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。0の行も必ず登録する。

## 11. セット商品の扱い

本ファイルにセット商品を判別する列は存在しない。セット商品はAmazon上では独立した出品として扱われるため、セット商品として特別な処理を行わず、`seller-sku`単位で在庫を登録する。

構成品在庫への引き当ては、[BOSS各在庫数レポート取込要件 第11章](02.BOSS各在庫数レポート取込要件.md)と同じく初期対象外とする。

## 12. 実データ検証結果

`参考/商品在庫取込データ/Amazon_FBA在庫.txt`（2026年8月27日出力）で次を確認した。

| 確認項目 | 結果 |
|---|---|
| ファイル形式 | Shift_JIS（CP932）、CRLF、タブ区切り、全1328行が6列 |
| 列構成 | `seller-sku`、`fulfillment-channel-sku`、`asin`、`condition-type`、`Warehouse-Condition-code`、`Quantity Available` |
| 行数 | 1327行（項目名行を除く） |
| 一意性 | `seller-sku`は1327件すべて一意。`asin`は129件が重複する |
| `condition-type` | 全1327行が`NewItem` |
| `Warehouse-Condition-code` | 全1327行が`SELLABLE` |
| `Quantity Available` | 合計4708、最大40、`0`が913行。空欄および負値なし |
| 空欄 | 全6列に空欄なし |
| SKUの表記 | 200件が内部に半角空白を含む（例：`FI7018-1 +1.50`）。日本語を含むものが1件（`7003-9-ラベルなしの混合在庫`） |
| BOSS `SKUコード`との突合 | 完全一致43件、英字の大小を無視した一致311件 |
| 出品詳細レポートとの突合 | 1189子ASINのうち576子ASIN（578行）が出品詳細レポートに存在しない。その578行は`Quantity Available`がすべて`0`である |

出品詳細レポートに存在しない578行が実データですべて`0`であることは、本サンプルでの観察であり、常に成立する保証ではない。FBA在庫はFBA在庫レポートを正本とし、出品詳細レポートへの掲載の有無で取込対象を絞らない。
