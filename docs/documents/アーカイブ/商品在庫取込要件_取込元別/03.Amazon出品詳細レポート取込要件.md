# Amazon出品詳細レポート取込要件

> 本書は2026年10月1日に廃止した。在庫は別システムが出力する日次在庫CSVから取り込む方式へ変更しており、現行の要件は[商品在庫取込要件](../../商品在庫取込要件/01.商品在庫取込要件.md)に定める。本書は旧取込元の調査結果として参照専用で残す。

- 文書状態：確定版
- 更新日：2026年8月31日
- 対象システム：商品在庫管理システム
- 実データ検証状況：出品詳細レポート 確認済み

本書は、Amazon Seller Centralの出品詳細レポートに固有の取込要件を定める。`Amazon自社倉庫`の在庫が対象である。  
全取込元に共通する方針は[01.商品在庫取込要件](../../商品在庫取込要件/01.商品在庫取込要件.md)に、保存項目の全体像と共通の保存形式は[05.商品在庫保存データ](../../商品在庫取込要件/03.商品在庫保存データ.md)に定める。  
章構成は[02.BOSS各在庫数レポート取込要件](02.BOSS各在庫数レポート取込要件.md)および[04.Amazon FBA在庫レポート取込要件](04.AmazonFBA在庫レポート取込要件.md)と共通であり、その定義は[商品在庫取込要件 第4.6節](../../商品在庫取込要件/01.商品在庫取込要件.md)による。

## 1. 入力ファイル

| 項目     | 内容                              |
| ------ | ------------------------------- |
| 取得元    | Amazon Seller Centralの出品詳細レポート  |
| ファイル形式 | テキストファイル                        |
| 区切り文字  | タブ                              |
| 文字コード  | UTF-8（BOM付き）またはShift_JIS（CP932） |
| 改行コード  | LF                              |
| 項目名    | 1行目                             |
| データ構造  | 1出品につき1行                        |
| 列数     | 6列                              |

文字コードは、BOMおよびUTF-8としての妥当性を確認して判定し、UTF-8でない場合はShift_JIS（CP932）として読み込む。判定規則は[Amazon全注文レポート取込要件 第1章](../../販売実績取込要件/03.Amazon全注文レポート取込要件.md)と同一である。同じSeller Centralから取得したファイルでも、[Amazon FBA在庫レポート取込要件 第1章](04.AmazonFBA在庫レポート取込要件.md)とは文字コードおよび改行コードが異なるため、ファイルごとに判定する。

列名は日本語である。`ASIN 1`のように列名の内部に半角空白を含む列があるため、列名の前後の空白だけを除去し、内部の空白を除去しない。

本ファイルに相当するSP-APIのレポート種別は未確定である。列構成が確認できるのはSeller Centralの画面から出力した実データだけであるため、レポート種別の指定によって列構成を確定させない。

## 2. 必須列・値の扱い

出品詳細レポートには、最低限次の列が必要である。  
ここでの必須とは列の存在を意味し、各行の値が空欄であることを一律に取込エラーとするものではない。

| 列名 | 用途 | 値の必須 |
|---|---|---|
| `出品者SKU` | 一意キーおよび取込元SKU | 必須 |
| `ASIN 1` | 取込元商品ID | 必須 |
| `数量` | Amazon自社倉庫の在庫数、および取込対象の判定 | 空欄を許容 |

`商品名`、`商品ID`および`価格`は取り込まないため（第9章）、必須列としない。

第3章により取込対象とした行では、上表で値を必須とした列に値が存在することを要する。  
値の必須条件を満たさない行の扱いは[取込エラー・警告 第3章](../../商品在庫取込要件/06.取込エラー・警告.md)に定める。

## 3. 取込対象

`数量`に値がある行だけを`Amazon自社倉庫`の在庫として取り込む。  
`数量`が空欄の行はFBA出品であり、Amazon自社倉庫の在庫管理対象ではないため、在庫数を登録しない。空欄を`0`として登録しない。

### 3.1 空欄をFBA出品と判定する根拠

実データで次を確認している。

- 全790行のうち602行の`数量`が空欄であり、そのうち599行の子ASINがFBA在庫レポートに存在する。
- Amazon全注文レポートで`fulfillment-channel`が`Merchant`であった5商品の子ASINは、すべて出品詳細レポートの`数量`に値があり、FBA在庫レポートに存在しない。
- Amazon全注文レポートで`fulfillment-channel`が`Amazon`であった商品の子ASINは、いずれも出品詳細レポートの`数量`が空欄である。

`数量`が空欄であることと、当該子ASINがFBA出品であることが実データで対応している。これにより、`数量`の空欄はFBA出品を表すものとして判定する。

### 3.2 いずれの倉庫にも登録されない商品

`数量`が空欄であり、かつ同一の子ASINが同一在庫基準日のFBA在庫レポートにも存在しない商品は、いずれの倉庫区分の在庫としても登録されない。実データでは3件（Amazon SKUは`FISI04`、`FLL-3004`、`SPC-007`）が該当する。

この判定は他の取込元の取込結果を必要とするため、ファイル単位ではなく、同一在庫基準日の全取込元の取込完了後に倉庫横断の警告として記録する（[取込エラー・警告 第4章](../../商品在庫取込要件/06.取込エラー・警告.md)）。

### 3.3 FBA在庫レポートと重複する商品

`数量`に値があり、かつ同一の子ASINがFBA在庫レポートにも存在する商品が実データで14件ある。いずれも同じ子ASINに属するFBA在庫レポートの`Quantity Available`合計が`0`であり、FBA出荷からの切り替えに伴う残存登録と考えられる。

倉庫区分が異なるため、両方を取り込んでも二重計上にならない。`Amazon自社倉庫`の在庫として`数量`を、`FBA`の在庫として`Quantity Available`を、それぞれ別レコードとして登録する。合算しない（[商品在庫取込要件 第4.2節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。

## 4. 在庫基準日

ファイルに在庫基準日を示す列は存在しない。在庫基準日は担当者が取込時に指定する（[商品在庫取込要件 第4.3節](../../商品在庫取込要件/01.商品在庫取込要件.md)、[取込処理・運用要件 第2章](../../商品在庫取込要件/05.取込処理・運用要件.md)）。

Seller Centralからダウンロードしたファイルの名称に出力日が含まれる場合がある（実データの元ブックでは`出品詳細レポート_08-27-2026`）が、ファイル名は在庫基準日の判定に使用しない。

## 5. 倉庫区分

倉庫区分を判定する列は存在しない。取込対象とした行の倉庫区分は`Amazon自社倉庫`固定とする。

| 判定元 | 倉庫区分 |
|---|---|
| 判定列なし（ファイル種別と`数量`の有無で確定） | `Amazon自社倉庫` |

`fulfillment-channel`に相当する列は本ファイルに存在しない。出荷区分の判別は、第3章のとおり`数量`の空欄で行う。

## 6. 商品コードの解決

`ASIN 1`を子ASINとしてSKUマスタを参照し、システム内商品コードを特定する（[商品在庫取込要件 第5.2節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。

`出品者SKU`は、[Amazon全注文レポート取込要件 第9章](../../販売実績取込要件/03.Amazon全注文レポート取込要件.md)の`sku`と同じくSeller Centralで出品者が設定し変更できる値である。商品コード解決には使用せず、取込時点の表示値として在庫取込明細に保存する。

`ASIN 1`がSKUマスタの子ASINに存在しない行は、在庫を登録せず未対応ASINとして記録し、警告する。自動登録の対象としない。

実データでは、790件の`出品者SKU`のうちBOSSの`SKUコード`と完全一致するものが73件、英字の大小を無視して一致するものが353件である。この一致件数は参考情報であり、Amazon SKUの完全一致または表記加工による対応付けは行わない。

## 7. 一意キー・重複行の扱い

一意キーには`出品者SKU`を使用する。実データでは790件すべてが一意である。

`ASIN 1`はファイル行の一意キーには使用しない。同一商品に過去および現在の複数の`出品者SKU`が存在しうるため、同一の子ASINが複数行に現れることを許容する。子ASINは商品識別キーとして使用する。

同一ファイル内に同一`出品者SKU`の行が複数存在した場合は、ファイル内で最初に出現した1行だけを取込対象とし、2行目以降は行単位の取込エラーとして記録し、登録しない。この扱いは[Amazon全注文レポート取込要件 第7章](../../販売実績取込要件/03.Amazon全注文レポート取込要件.md)と同じであり、BOSSとは異なる（[BOSS各在庫数レポート取込要件 第7章](02.BOSS各在庫数レポート取込要件.md)）。

重複行を除外して商品コードを解決した後、同一の`ASIN 1`から同じシステム内商品コードへ解決された複数行は同一商品として扱う。各行を在庫取込明細へ保存し、`数量`を合計して`Amazon自社倉庫`の在庫数を1件登録する。

## 8. 保持する在庫数量項目

次の項目を在庫取込明細へ保存し、商品単位に集約した販売可能在庫を在庫数へ保存する。

| 保存項目 | 取得元 |
|---|---|
| 販売可能在庫 | `数量` |
| 取込元SKU | `出品者SKU` |
| 取込元商品ID | `ASIN 1` |

`数量`は出品者が設定した販売可能数量であり、引当済を除いた出荷可能な数量である。BOSSのように実在庫数と引当済数へ分解することはできないが、保存するのは販売可能在庫だけであるため、`数量`をそのまま販売可能在庫として採用する（[商品在庫取込要件 第4.5節](../../商品在庫取込要件/01.商品在庫取込要件.md)）。

`Amazon自社倉庫`に物理的に存在する総在庫数は、本ファイルからは取得できない。

## 9. 取り込まない項目

次の列は保存しない。

| 列名 | 取り込まない理由 |
|---|---|
| `商品名` | Amazon上の商品名であり、SKUマスタの商品名と体系が異なる。在庫管理に不要である |
| `価格` | 在庫管理に不要である。実データでは全790行に値がある |
| `商品ID` | JANコードとASINが混在する。実データでは790行のうち502行が13桁の数字（JANコード）、288行が`ASIN 1`と同値である。取込元商品IDには`ASIN 1`を使用する |

`商品ID`は担当者が商品を確認する際の補助情報として参照することを妨げないが、取込処理では使用せず保存もしない。

## 10. 0在庫・マイナス在庫の扱い

- `数量`が`0`の行は在庫0として登録する。実データでは188行のうち73行が`0`である。
- `数量`の空欄と`0`は区別する。空欄はFBA出品であり登録せず（第3章）、`0`はAmazon自社倉庫に在庫がないことを表す。
- `数量`が負値の場合は、`0`へ補正せずそのまま登録し、警告を記録する。実データに負値は存在しない。

## 11. セット商品の扱い

本ファイルにセット商品を判別する列は存在しない。セット商品はAmazon上では独立した出品として扱われるため、セット商品として特別な処理を行わず、`出品者SKU`単位で在庫を登録する。

構成品在庫への引き当ては、[BOSS各在庫数レポート取込要件 第11章](02.BOSS各在庫数レポート取込要件.md)と同じく初期対象外とする。

## 12. 実データ検証結果

`参考/商品在庫取込データ/Amazon_出品詳細レポート.txt`（2026年8月27日出力）で次を確認した。

| 確認項目 | 結果 |
|---|---|
| ファイル形式 | UTF-8（BOM付き）、LF、タブ区切り、全791行が6列 |
| 列構成 | `出品者SKU`、`ASIN 1`、`商品名`、`商品ID`、`価格`、`数量` |
| 行数 | 790行（項目名行を除く） |
| 一意性 | `出品者SKU`は790件すべて一意 |
| `数量` | 空欄602行、値あり188行。値ありのうち`0`が73行。合計321、最大27 |
| 空欄行とFBA在庫レポート | 空欄602行のうち599行の子ASINがFBA在庫レポートに存在。存在しないAmazon SKUは`FISI04`、`FLL-3004`、`SPC-007`の3件 |
| 値あり行とFBA在庫レポート | 値あり188行のうち14行の子ASINがFBA在庫レポートに存在し、いずれも同じ子ASINの`Quantity Available`合計が`0` |
| 全注文レポートとの突合 | `fulfillment-channel`が`Merchant`のSKU5件はすべて`数量`に値あり。`Amazon`のSKUはすべて`数量`が空欄 |
| `ASIN 1`と`商品ID` | 790行のうち502行で異なる。異なる行の`商品ID`はいずれも13桁の数字である |
| `価格` | 空欄なし |
| SKUの表記 | 88件が内部に半角空白を含む（例：`FIFLC-002-1 +1.00`） |
| BOSS `SKUコード`との突合 | 完全一致73件、英字の大小を無視した一致353件 |
| FBA在庫レポートとの網羅性 | FBA在庫レポートの1189子ASINのうち576子ASINが本ファイルに存在しない |
