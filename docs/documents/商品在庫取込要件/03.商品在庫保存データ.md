# 商品在庫保存データ

- 文書状態：改訂案
- 更新日：2026年10月1日
- 対象システム：商品在庫管理システム

本書は、取り込んだ在庫の保存形式および保存項目を定める。  
入力ファイルの列と変換規則は[02.日次在庫CSV取込要件](02.日次在庫CSV取込要件.md)に、共通の方針は[01.商品在庫取込要件](01.商品在庫取込要件.md)に定める。

日次在庫CSVの列構成のまま保存せず、倉庫区分ごとの行へ変換して保存する。  
在庫の正本は`在庫数`とし、取込処理の証跡は`取込履歴`と`取込指摘`に保存する。  
本書に定義する項目以外、および商品属性等のマスタ側で管理する項目は保存しない。

## 1. データ構成

| 保存データ | 1レコードの単位 | 主な関係 |
| --- | --- | --- |
| 在庫数 | 在庫基準日、倉庫区分およびSKUの組合せ | 最後に登録・更新した取込履歴を参照する。手入力の場合は参照しない |
| 倉庫マスタ | 1つの倉庫区分 | 在庫数から参照される |
| 取込履歴 | 1回のファイル取込 | 複数の在庫基準日の在庫数を登録・更新しうる |
| 取込指摘 | 1回の取込で検出した警告またはエラー1件 | 取込履歴に属し、該当する在庫基準日・倉庫区分・SKU・元ファイル行を特定する |

```text
取込履歴 1 ── N 取込指摘
   │
   └── 最終更新元 ── N 在庫数 ── 参照 ── 倉庫マスタ
                         │
                         └── 参照 ── SKUマスタ
```

SKUマスタは販売実績と共通であり、在庫のために別途保持しない。

旧版で設けていた在庫基準、在庫取込および在庫取込明細は廃止した。在庫基準は複数の取込元の揃い具合を、在庫取込明細は同一子ASINに属する複数のAmazon出品行の追跡を目的としていたが、取込元が日次在庫CSVの1つとなり、1行に4倉庫区分の在庫が揃い、ASINの対応付けを在庫取得システムが行うため不要となった。

### 1.1 保存形式の選択

在庫を保持する構造には、次の2つの形式が考えられる。日次在庫CSVは列展開形式である。

| 形式 | 1レコードの単位 | 在庫数量の持ち方 |
| --- | --- | --- |
| 行分割形式 | 在庫基準日、倉庫区分およびSKUの組合せ | 1レコードに1倉庫区分の販売可能在庫を持つ |
| 列展開形式 | 在庫基準日およびSKUの組合せ | 1レコードに4倉庫区分の販売可能在庫を列として持つ |

本システムでは行分割形式を採用する。理由は次のとおりである。

- **販売実績と同じ軸で結合できる。** 欠品判定および需要按分は倉庫区分単位で行い、販売実績の`出荷倉庫`と倉庫区分で結合する（[在庫利用要件 第3章](04.在庫利用要件.md)）。列展開形式では列名から倉庫区分への読み替えが計算のたびに必要になる。
- **手入力を倉庫区分ごとに区別できる。** 棚卸結果の手入力は倉庫区分ごとに行い、取得区分、手入力者および手入力日時を倉庫区分ごとに持つ（第8章）。列展開形式ではこれらを4倉庫区分分だけ列として持つ必要がある。
- **未取得と在庫0を区別できる。** 当該倉庫区分の在庫が0であることと、当該倉庫区分の在庫をまだ取得できていないことを、レコードの有無で区別できる。
- **倉庫の追加時に保存データの定義を変更せずに済む。** 倉庫区分は本要件の設計過程でも3区分から4区分へ変更されており、今後も追加されうる。

SKU1行に対して倉庫別の在庫数を横並びに表示する形式は、画面および出力の表示形式として第7章に定める。

### 1.2 レコード件数の試算

日次で取り込み、暦日365日すべてに在庫基準日がある場合を上限として試算した。倉庫区分は4区分である。

| SKU数の前提 | 1在庫基準日あたり | 年間 | 5年間 |
| --- | --- | --- | --- |
| 実データの272SKU | 1,088件 | 397,120件 | 1,985,600件 |
| BOSSの全SKU（1530件） | 6,120件 | 2,233,800件 | 11,169,000件 |

全SKUを日次で5年保持しても約1,100万件であり、性能上の制約にならないため、レコード件数を保存形式の判断材料としない。

在庫は取込のたびにその時点の残高を追加登録するため、件数は在庫基準日の数に比例して増える。販売実績は販売数量にだけ比例するため、増え方が異なる（[販売実績保存データ 第1.1節](../販売実績取込要件/04.販売実績保存データ.md)）。将来、件数が問題となった場合も、保存形式の変更ではなく保持年数の制限で対応する。保持年数の設定は[要件定義書 第10.2節](../要件定義書.md)のデータ保持方針に従う。

## 2. 共通の保存規則

- 内部IDはシステムが付与し、取込元のSKUとは分けて保持する。内部IDの物理的な型は詳細設計で決定する。
- SKUは先頭の0や桁数を失わないよう文字列として保存する。英字の大小および内部の空白を保持する（[商品在庫取込要件 第6.1節](01.商品在庫取込要件.md)）。
- 在庫基準日は日付として保存する。時刻を持たせない。
- 在庫数量は整数で保存する。負値を許容し、取込時に0へ補正しない。
- 在庫数は物理削除しない。
- 保存する在庫数量は販売可能在庫の1項目だけとする。実在庫数および引当済数は保存しない（[商品在庫取込要件 第5.5節](01.商品在庫取込要件.md)）。

## 3. 在庫数

在庫の正本である。一意制約は`在庫基準日 + 倉庫区分 + システム内商品コード`とする。再取込時はこの組み合わせで既存レコードを特定して更新する。

| 保存項目 | 内容 | 日次在庫CSVからの取得 | 必須 |
| --- | --- | --- | --- |
| 在庫数ID | システムが付与する内部ID | 自動付与 | 必須 |
| 在庫基準日 | 在庫が成立した日 | `date` | 必須 |
| 倉庫区分 | `BOSS自社倉庫`、`RFC`、`Amazon自社倉庫`または`FBA` | 列名から判定（[日次在庫CSV取込要件 第5章](02.日次在庫CSV取込要件.md)） | 必須 |
| システム内商品コード | BOSSの`SKUコード`と同一の商品コード | `sku` | 必須 |
| 販売可能在庫 | 当該倉庫から出荷に充てられる数量 | 倉庫区分に対応する列の値 | 必須 |
| 取得区分 | `自動取込`または`手入力` | `自動取込` | 必須 |
| 最終取込履歴ID | このレコードを最後に登録・更新した取込 | 取込履歴ID | 取得区分が`自動取込`の場合は必須 |
| 元ファイル行番号 | 最後に登録・更新した取込における、項目名行を除くデータ行の位置 | 行番号 | 取得区分が`自動取込`の場合は必須 |
| 作成日時 | 初回登録日時 | 自動付与 | 必須 |
| 更新日時 | 最終更新日時 | 自動付与 | 必須 |

在庫数は、上表の項目に加えて第8章に定める手入力の項目を保持する。手入力の項目は取込では設定せず、再取込でも上書きしない。

## 4. 取込履歴

取込ごとに、少なくとも次の情報を保存する。

| 保存項目 | 内容 |
| --- | --- |
| 取込履歴ID | システムが付与する内部ID |
| 取込日時 | 取込を実行した日時 |
| 実行者 | 取込を実行した担当者 |
| ファイル名 | 取り込んだファイルの名称 |
| ファイルの識別情報またはハッシュ値 | 同一ファイルの再取込を識別する値 |
| 在庫基準日の範囲 | ファイルに含まれる在庫基準日の最小値と最大値 |
| 在庫基準日数 | ファイルに含まれる在庫基準日の件数 |
| ファイル内総行数 | 項目名行を除く入力ファイルの行数 |
| 新規登録件数 | 新規作成した在庫数の件数 |
| 更新件数 | 既存レコードの値を変更した件数 |
| 変更なし件数 | 既存レコードと値が同一のため更新しなかった件数 |
| SKU識別レコード自動登録件数 | 商品属性未設定のSKU識別レコードとして自動登録した件数 |
| 消失件数 | 直前の在庫基準日に存在し、当該在庫基準日に存在しなかったSKUの件数 |
| 手入力保持件数 | 手入力のため取込値で上書きしなかった件数 |
| 警告件数 | 記録した警告の件数 |
| エラー件数 | 記録したエラーの件数 |
| 処理結果 | 取込全体の処理結果 |

在庫数から最終取込履歴IDをたどることで、現在の値を登録または更新したファイル、取込日時および元ファイルの行を確認できるようにする。取込指摘の保存項目は[取込エラー・警告 第4章](06.取込エラー・警告.md)に定める。

## 5. 倉庫マスタ

倉庫区分ごとの属性を保持する。一意制約は`倉庫区分`とする。

倉庫マスタは在庫だけのマスタではない。[販売実績保存データ 第4.1節](../販売実績取込要件/04.販売実績保存データ.md)の出荷倉庫は、本マスタの倉庫区分と同一の値であり、販売実績と在庫の双方が本マスタを参照する。倉庫を追加する場合は、本マスタへの登録と併せて、販売実績側の出荷倉庫の変換規則および日次在庫CSVの列の対応も追加する。

| 保存項目 | 内容 | 必須 |
| --- | --- | --- |
| 倉庫区分 | `BOSS自社倉庫`、`RFC`、`Amazon自社倉庫`または`FBA` | 必須 |
| 倉庫名 | 画面表示に使用する名称 | 必須 |
| 保管主体 | `自社`、`楽天`または`Amazon` | 必須 |
| 出荷対象モール | 当該倉庫から出荷するモールコード。複数を保持する | 必須 |
| 日次在庫CSVの列名 | 当該倉庫区分の在庫数を持つ列 | 必須 |
| 補充元倉庫区分 | 当該倉庫を補充する倉庫区分 | 任意 |
| 在庫鮮度許容日数 | 在庫基準日からの経過日数の許容値 | 必須 |
| 有効・無効状態 | 当該倉庫を現在使用するか | 必須 |

初期の登録内容は[商品在庫取込要件 第2章](01.商品在庫取込要件.md)の表のとおりとする。

補充元倉庫区分は、必要在庫数の算出で外部倉庫への補充を扱うために設ける（[在庫利用要件 第5章](04.在庫利用要件.md)）。実際の補充関係は未確定であるため、初期値を設定せず`NULL`とし、確定後に登録する。

## 6. 追加登録と再取込時の保存結果

在庫数は上書きせず、在庫基準日ごとに追加登録して蓄積する（[商品在庫取込要件 第5.4節](01.商品在庫取込要件.md)）。

- 一意キーが未登録の場合は、在庫数を新規作成する。
- 一意キーが登録済みで値が異なる場合は、既存レコードの販売可能在庫を更新し、更新日時、最終取込履歴IDおよび元ファイル行番号を今回の取込に変更する。内部IDと作成日時は変更しない。
- 一意キーが登録済みで値が同一の場合は、レコードを更新しない。過去日を含むファイルを繰り返し取り込んでも、更新日時および最終取込履歴IDを変化させない。
- ファイルに含まれない在庫基準日のレコードは変更しない。
- 当該在庫基準日のファイルに含まれないSKUの既存レコードは、削除も`0`への書き換えもしない。
- 直前の在庫基準日に存在し、当該在庫基準日に存在しないSKUは、消失件数として取込履歴に記録し、警告する（[取込エラー・警告 第3章](06.取込エラー・警告.md)）。
- 取得区分が`手入力`のレコードは、再取込で上書きしない（第8章）。

### 6.1 受入条件

| 操作 | 期待結果 |
| --- | --- |
| 新しい在庫基準日を含む日次在庫CSVを取り込む | 1行につき4倉庫区分の在庫数を新規登録し、他の在庫基準日のレコードを変化させない |
| 同一ファイルを再取込する | 在庫数および倉庫別の合計が変化せず、レコードが二重登録されず、更新日時も変化しない |
| 取込済みの在庫基準日の値を訂正したファイルを取り込む | 値が異なるレコードだけを更新し、最終取込履歴IDと更新日時が今回の取込に変わる |
| 直前の在庫基準日に存在したSKUを含まない在庫基準日を取り込む | 当該SKUを`0`として登録せず、消失件数と警告を記録する |
| 1列だけ数値でない行を含むファイルを取り込む | 当該行の4倉庫区分をいずれも登録せず、他の行を登録する |
| 手入力で登録した在庫数と同じ在庫基準日・倉庫区分・SKUを含むファイルを取り込む | 手入力のレコードが保持され、取込値で上書きされず、警告を記録する |
| SKUマスタに存在しない`sku`を取り込む | SKU識別レコードを自動登録し、在庫数を登録する |

## 7. 最新在庫の特定と表示上の集計

### 7.1 最新在庫の特定

在庫試算の現在庫には、次のとおり在庫数を採用する。

- SKU・倉庫区分ごとに、試算の基準日以前で最新の在庫基準日のレコードを採用する。手入力のレコードを含むため、倉庫区分によって採用した在庫基準日が異なる場合がある。採用した在庫基準日を倉庫区分ごとに保持し、画面に表示する。
- 試算の基準日と採用した在庫基準日の差が、倉庫マスタの在庫鮮度許容日数を超える場合は警告する。
- 在庫試算の対象SKUについて、基準日以前の在庫数が1件も存在しない倉庫区分は在庫未取得として警告する。欠損として`0`を補わない。
- 在庫試算では、各倉庫区分の最新の在庫基準日と在庫数を使用する。試算条件および結果は保存しない（[要件定義書 第10.3節](../要件定義書.md)）。

### 7.2 表示上の集計

倉庫別の合計値は保存せず、表示時に集計する（[商品在庫取込要件 第5.2節](01.商品在庫取込要件.md)）。SKU1行に対して倉庫別の在庫数を横並びに表示する形式は、次のとおり在庫数から生成する。

| 表示列 | 生成元 |
| --- | --- |
| SKU | `在庫数.システム内商品コード` |
| BOSS自社倉庫在庫数 | 倉庫区分`BOSS自社倉庫`の販売可能在庫 |
| RFC倉庫在庫数 | 倉庫区分`RFC`の販売可能在庫 |
| Amazon自社倉庫在庫数 | 倉庫区分`Amazon自社倉庫`の販売可能在庫 |
| FBA倉庫在庫数 | 倉庫区分`FBA`の販売可能在庫 |
| 合計在庫数 | 上記4列の合計 |

```text
合計在庫数 = Σ(倉庫区分ごとの販売可能在庫)
```

- 当該SKU・当該倉庫区分の在庫数が存在しない場合は、`0`ではなく未取得として表示する。
- 未取得の倉庫区分がある場合、合計在庫数は実際の合計を下回る。合計値には未取得の倉庫区分があることを併記する。
- 各列に、採用した在庫基準日と在庫基準日からの経過日数を確認できるようにする。
- 合計在庫数は表示のための派生値であり、欠品判定および必要在庫数の算出には使用しない（[在庫利用要件](04.在庫利用要件.md)）。

## 8. 手入力による在庫の登録・修正

実地棚卸の結果の反映など、日次在庫CSVから取得できない在庫を担当者が手入力できる。 [要件定義書 FR-050](../要件定義書.md) の「在庫の取得元、取得日時および自動取得・手入力の区分を保持すること」に対応する。

手入力では、在庫数の取得区分を `手入力` とし、次の項目を追加で保持する。

| 保存項目 | 内容 | 必須 |
| --- | --- | --- |
| 手入力メモ | 担当者が任意に入力する補足 | 任意 |
| 手入力者 | 最後に手入力を行った担当者 | 取得区分が `手入力` の場合は必須 |
| 手入力日時 | 最後に手入力を行った日時 | 取得区分が `手入力` の場合は必須 |

手入力の規則は次のとおりとする。

- 手入力で登録・修正したレコードは、取得区分を `手入力` に変更し、再取込で上書きしない。
- 手入力のレコードと同じ在庫基準日・倉庫区分・SKUを含むファイルを取り込んだ場合は、確認用の警告を記録する（[取込エラー・警告 第3章](06.取込エラー・警告.md)）。
- 手入力のレコードを取込値に戻す操作は、担当者が取得区分を `自動取込` へ戻したうえで再取込することによる。自動では戻さない。
- 手入力値と自動取込値を画面上で識別できるようにする（[要件定義書 FR-071](../要件定義書.md)）。
- 過去の在庫基準日のレコードに対する手入力も許可する。ただし在庫数の変更履歴は保持し、変更前後の値、理由、変更者および変更日時を確認できるようにする。

在庫数の変更履歴として保存する項目は未確定である。
