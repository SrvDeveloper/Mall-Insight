# 在庫利用要件

- 文書状態：改訂案
- 更新日：2026年10月1日
- 対象システム：商品在庫管理システム

本書は、取り込んだ在庫を用いて欠品発生時期および必要在庫数を求めるために必要なデータと構造を定める。  
計算式そのものは[要件定義書 FR-060、FR-061、FR-062](../要件定義書.md)に定義済みであり、本書ではそれらを倉庫区分単位で適用するために必要な要件だけを定める。取り込んだ在庫の保存形式は[03.商品在庫保存データ](03.商品在庫保存データ.md)に定める。

## 1. 確認したい情報

商品在庫管理によって、[要件定義書 FR-042](../要件定義書.md)に基づき担当者が確定した売上上位20品番に属するSKUについて、次を確認できるようにする。在庫取込と在庫照会は日次在庫CSVに含まれる全SKUを対象とするが、12か月在庫試算、欠品判定および必要在庫数の算出は確定した対象品番のSKUだけに限定する。

| 確認したい情報 | 出力 |
|---|---|
| いつ在庫切れが発生するか | 倉庫区分ごとの欠品予測日または欠品予測月 |
| どれだけの在庫が必要か | 倉庫区分ごとの安全在庫、補充必要数および必要在庫数 |

いずれも倉庫区分単位で求める。SKU単位の合計在庫からは求めない。

## 2. 倉庫区分単位で判定する理由

在庫は倉庫区分ごとに独立した引当の対象であり、ある倉庫の在庫を別の倉庫の出荷に充てることはできない。合計在庫が需要を上回っていても、特定の倉庫では欠品しうる。

このため、[商品在庫保存データ 第7.2節](03.商品在庫保存データ.md)の合計在庫数は表示のための派生値とし、欠品判定および必要在庫数の算出には使用しない。判定は次の4つの倉庫区分について個別に行う。

- `BOSS自社倉庫`
- `RFC`
- `Amazon自社倉庫`
- `FBA`

## 3. 倉庫区分別の需要

### 3.1 倉庫区分別の販売実績

販売実績は注文明細ごとに出荷倉庫を保持している（[販売実績保存データ 第4.1節](../販売実績取込要件/04.販売実績保存データ.md)）。出荷倉庫は在庫の倉庫区分と同一の語彙であるため、`販売注文明細.出荷倉庫`で販売数量を集計すれば、倉庫区分別の販売実績が得られる。変換も、モールコードとの組合せも必要としない。

| 販売注文明細.出荷倉庫 | 倉庫区分 |
|---|---|
| `BOSS自社倉庫` | `BOSS自社倉庫` |
| `RFC` | `RFC` |
| `Amazon自社倉庫` | `Amazon自社倉庫` |
| `FBA` | `FBA` |

モールコードから倉庫区分を推定しない。`RFC`は楽天市場専用ではなく、実データでは`RFC倉庫`からの出荷が楽天市場86件、Yahoo!ショッピング63件、au PAY マーケット4件に発生している。`RFC`の需要を楽天市場の販売実績だけから算出しない。

`BOSS自社倉庫`の需要は楽天市場、Yahoo!ショッピングおよびau PAY マーケットの3モールの合算となる。この3モールは同一の在庫から出荷されるため、需要をモール別に分けずに1つの倉庫区分として扱う。

集計は`販売計上状態 = 計上`の販売注文明細だけを対象とし、純販売数量を用いる（[販売実績保存データ 第9章](../販売実績取込要件/04.販売実績保存データ.md)）。

### 3.2 倉庫区分別平均日販

```text
倉庫区分別平均日販 = 倉庫区分別の対象期間純販売数量 ÷ 販売可能日数
```

販売可能日数の定義は[要件定義書 第5章](../要件定義書.md)および[FR-010](../要件定義書.md)による。欠品日および販売停止日を除外する規則を、倉庫区分単位でも適用する。ある倉庫が欠品していた日は、その倉庫の販売可能日数から除外する。

### 3.3 倉庫区分別需要予測

システム需要予測はSKU単位で算出される（[要件定義書 FR-011](../要件定義書.md)）。倉庫区分別の需要は、SKU単位の需要予測を倉庫区分別の実績構成比で按分して求める。

```text
倉庫区分別需要構成比 = 倉庫区分別の対象期間純販売数量 ÷ 同一SKUの全倉庫区分の対象期間純販売数量
倉庫区分別需要予測   = SKU別システム需要予測 × 倉庫区分別需要構成比
```

- 按分後の倉庫区分別需要予測の合計を、按分前のSKU別システム需要予測に一致させる。丸めによる差は、構成比が最大の倉庫区分で調整する。
- 構成比の算出には、欠品を補正した後の実績を使用する（[要件定義書 FR-016](../要件定義書.md)）。補正しない実績を使用すると、欠品していた倉庫の構成比が小さく算出され、欠品状態を追認した需要按分になる。
- 販売実績が1件もないSKUおよび倉庫区分では構成比を算出できない。この場合の扱いは第7章の未確定事項とする。

倉庫区分別需要予測は保存しない。SKU別システム需要予測（SKU×対象月）と倉庫区分別需要構成比（SKU×倉庫区分）をそれぞれ予測バージョンに保存し、両者の積として必要なときに算出する（[要件定義書 第10.3節](../要件定義書.md)）。SKU×倉庫区分×対象月のデータを作らないことで、保存件数が倉庫区分の数だけ増えることを避ける。

保存する需要構成比には、その算出期間および算出日時を含める。

年間販売目標は倉庫区分別需要予測の算出に使用しない（[要件定義書 第6章](../要件定義書.md)）。

## 4. 欠品発生時期

### 4.1 在庫日数と欠品予測日

```text
在庫日数   = 販売可能在庫 ÷ 倉庫区分別平均日販
欠品予測日 = 在庫基準日 + 在庫日数
```

倉庫区分別平均日販が0の場合は在庫日数を算出せず、欠品予測日を`欠品予測なし`とする。0除算の結果を無限大や0として扱わない。

### 4.2 月次在庫推移における欠品予測月

[要件定義書 FR-060](../要件定義書.md)の月次計算式を、倉庫区分ごとに適用する。

```text
月末在庫   = MAX(0, 月初在庫 + 確定入荷数 - 倉庫区分別需要予測)
未充足需要 = MAX(0, 倉庫区分別需要予測 - 月初在庫 - 確定入荷数)
```

未充足需要が初めて正の値となる月を、当該倉庫区分の欠品予測月とする。

月別の月末在庫および未充足需要は保存せず、表示のつど算出する。算出対象は担当者が確定した20品番に属するSKUだけとする。保存するのは、確定した試算について対象SKUと倉庫区分ごとの結論（欠品予測月、推定不足数、推奨発注数、必要在庫数）だけとする（[要件定義書 第10.3節・FR-070](../要件定義書.md)）。

### 4.3 月内の欠品発生時期

月次計算では、月内のどの時点で欠品するかを直接は求められない。当月の需要が月内で均等に発生すると仮定し、日数按分で求める。

```text
月内欠品予測日 = 月初日 + (月初在庫 + 確定入荷数) ÷ (当月の倉庫区分別需要予測 ÷ 当月日数)
```

この値は近似である。将来の月については日単位の在庫推移を算出しないことによる。画面には日単位の確定した欠品日としてではなく、欠品時期の目安として表示し、均等按分による近似であることを明示する。

確定入荷が月内の特定日に発生する場合、均等按分の仮定はその日の前後で成立しない。入荷予定日を考慮した按分を行うかは第7章の未確定事項とする。

### 4.4 欠品警告

[要件定義書 FR-061](../要件定義書.md)の警告条件を、倉庫区分ごとに適用する。

```text
在庫日数 < 調達リードタイム + 安全在庫日数
```

調達リードタイムおよび安全在庫日数は倉庫区分によって異なる。自社倉庫への仕入入荷と、自社倉庫からFBA倉庫またはRFC倉庫への納品では、所要日数が異なるためである。[要件定義書 第10.1節](../要件定義書.md)の調達マスタは現在SKU単位であり、倉庫区分の軸を持たない。倉庫区分別に保持するよう拡張する必要がある（第7章）。

警告には、欠品時期、推定不足数、次回入荷予定、警告理由に加えて、対象の倉庫区分と採用した在庫基準日を表示する。

## 5. 必要在庫数

### 5.1 倉庫区分別の安全在庫と補充必要数

[要件定義書 FR-062](../要件定義書.md)の式を、倉庫区分ごとに適用する。

```text
倉庫区分別安全在庫   = 倉庫区分別平均日販 × 安全在庫日数
倉庫区分別補充必要数 = MAX(0, リードタイム期間の倉庫区分別需要予測 + 倉庫区分別安全在庫 - 販売可能在庫 - 入荷予定数)
```

入荷予定は[要件定義書 FR-051](../要件定義書.md)に基づきSKU×倉庫区分単位で保持する。倉庫区分別補充必要数の算出では、当該倉庫区分に対する入荷予定のうち、在庫試算へ反映する確度の予定数量だけを入荷予定数に含める。確度`入荷済`の入荷予定は将来の入荷予定数に含めない。

### 5.2 外部倉庫への補充を含む必要在庫数

`RFC`および`FBA`は自社が保管しない倉庫であり、自社倉庫から納品して補充する。したがって自社倉庫に必要な在庫は、自社倉庫自身の需要だけでは決まらない。

```text
倉庫区分別必要在庫数 = 倉庫区分別補充必要数 + Σ(当該倉庫を補充元とする倉庫区分の補充必要数)
```

補充元と補充先の関係は倉庫マスタの補充元倉庫区分で表す（[商品在庫保存データ 第5章](03.商品在庫保存データ.md)）。`RFC`の補充元、および`FBA`の補充元が`BOSS自社倉庫`と`Amazon自社倉庫`のいずれであるかは確定していないため、初期値を設定しない。確定するまでは倉庫区分別補充必要数だけを表示し、補充を含む必要在庫数を算出しない（第7章）。

補充元倉庫区分が確定した後は、補充先の需要が補充元の需要に加算される。補充元の欠品判定にも同じ加算を反映する。

### 5.3 発注数量の丸め

推奨発注数への変換、および発注ロット・最小発注数への切り上げは、[要件定義書 FR-062](../要件定義書.md)に従う。切り上げは最終段階でのみ行い、倉庫区分別の按分値には適用しない。倉庫区分別に按分した数量を丸めた場合は、丸め後の合計を按分前の値に一致させる。

## 6. 在庫の鮮度

### 6.1 鮮度の表示と警告

- 倉庫区分ごとに、採用した在庫基準日と、そこからの経過日数を画面に表示する。
- 経過日数が倉庫マスタの在庫鮮度許容日数を超える倉庫区分は警告する（[商品在庫保存データ 第7.1節](03.商品在庫保存データ.md)）。
- 在庫基準日が古いほど欠品予測日および必要在庫数の誤差は拡大する。誤差を補正して表示しない。

### 6.2 推定現在庫

採用した在庫基準日が表示日より前の場合、その在庫と日次の販売実績を組み合わせ、在庫基準日以降の販売数量を差し引いた推定現在庫を併記できる。

```text
推定現在庫
  = 在庫基準日の販売可能在庫
  + 在庫基準日翌日以降の在庫補充数
  + 在庫基準日翌日以降の庫間移動入庫数
  - 在庫基準日翌日以降の庫間移動出庫数
  - 在庫基準日翌日以降の倉庫区分別純販売数量
```

- 推定現在庫は表示上の派生値であり、在庫数として保存しない。取り込んだ在庫と明確に区別して表示する。
- 補充実績は[要件定義書 FR-052](../要件定義書.md)に基づき入荷予定とは別に保持し、入荷予定を使用しない場合も直接登録できる。入荷予定の確度を`入荷済`へ変更する際は、当該入荷予定から区分`在庫補充`の補充実績を登録できる。
- 補充実績の数量は正の整数とし、区分`在庫補充`および`庫間移動入庫`は加算、`庫間移動出庫`は減算する。
- キャンセル・返品・返金が販売実績に反映されていない場合、その分だけ推定値は実際の在庫を下回る（[販売実績取込要件 第4.4節](../販売実績取込要件/01.販売実績取込要件.md)）。
- 推定現在庫を欠品判定および必要在庫数の算出に使用するかは第7章の未確定事項とする。

## 7. 必要なデータと未確定事項

欠品発生時期および必要在庫数の算出に必要なデータと、その定義状況は次のとおりである。

| 必要なデータ | 取得元 | 定義状況 |
|---|---|---|
| 倉庫区分別の販売可能在庫 | 日次在庫CSV | [商品在庫保存データ 第3章](03.商品在庫保存データ.md)で定義済み |
| 在庫基準日 | 日次在庫CSVの`date` | [商品在庫取込要件 第5.3節](01.商品在庫取込要件.md)で定義済み |
| 倉庫区分別の出荷倉庫 | 販売実績の`販売注文明細.出荷倉庫` | [販売実績保存データ 第4.1節](../販売実績取込要件/04.販売実績保存データ.md)で定義済み |
| 倉庫区分別の純販売数量 | 販売実績 | 第3.1節で定義済み |
| 倉庫区分別平均日販 | 販売実績から算出 | 第3.2節で定義済み |
| SKU別システム需要予測 | [要件定義書 FR-011](../要件定義書.md) | 定義済み |
| 試算対象品番の選定バージョン | [要件定義書 FR-042](../要件定義書.md) | 売上上位20品番をシステムが提示し、担当者が確定 |
| 倉庫区分別需要構成比 | 販売実績から算出し、予測バージョンに保存 | 第3.3節で定義済み |
| 倉庫マスタ | 本文書群 | [商品在庫保存データ 第5章](03.商品在庫保存データ.md)で定義済み |
| 入荷予定の倉庫区分 | [要件定義書 FR-051](../要件定義書.md) | 定義済み |
| 調達リードタイムの倉庫区分別値 | 調達マスタ | 倉庫区分の軸が未定義 |
| 安全在庫日数の倉庫区分別値 | 調達マスタ | 倉庫区分の軸が未定義 |
| 補充元倉庫区分 | 倉庫マスタ | 項目は定義済み、実際の補充関係が未確定 |
| 在庫鮮度許容日数 | 倉庫マスタ | 項目は定義済み、値が未確定 |
| 補充実績 | [要件定義書 FR-052](../要件定義書.md) | SKU、倉庫区分、補充日、数量および区分を定義済み |

実装開始前に、次を確定する。

1. 調達リードタイムおよび安全在庫日数を倉庫区分別に保持するか。保持する場合、調達マスタの定義をどう拡張するか。
2. `RFC`および`FBA`の補充元倉庫区分。`FBA`の補充元が`BOSS自社倉庫`と`Amazon自社倉庫`のいずれであるか。
3. 倉庫区分別需要構成比の算出期間。
4. 販売実績が1件もないSKUおよび倉庫区分の需要按分の方法。当該倉庫区分の需要を0とするか、他の倉庫区分または上位階層の構成比で補完するか。
5. 新規に出品した倉庫区分のように、在庫はあるが実績がない場合の扱い。
6. 在庫鮮度の許容日数と、超過時に在庫試算の実行を許可するか。
7. 推定現在庫を表示だけに使用するか、欠品判定および必要在庫数の算出にも使用するか。
8. 月内の欠品発生時期の按分で、入荷予定日を考慮するか。
9. 在庫の取込頻度（[商品在庫取込要件 第7章](01.商品在庫取込要件.md)）。
10. 取り込んだ日次在庫が0以下の日を、欠品日として自動で登録するか（[予測用実績の補正 第4.3節](../システム需要予測設計/02.予測用実績の補正.md)）。
