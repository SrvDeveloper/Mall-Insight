# 取込処理・運用要件

- 文書状態：改訂案
- 更新日：2026年10月1日
- 対象システム：商品在庫管理システム

本書は、商品在庫取込の処理順序と、取込頻度および初回取込の運用要件を定める。  
入力ファイルおよび検証の要件は[02.日次在庫CSV取込要件](02.日次在庫CSV取込要件.md)に、保存結果は[03.商品在庫保存データ](03.商品在庫保存データ.md)に定める。

## 1. 取込処理の流れ

取込処理は次の順序で実行する。

1. ファイルを選択する。在庫基準日は指定しない。
2. 文字コード、区切り文字を判定する。BOMがある場合は除去する。
3. 列名の前後空白を除去する。内部の空白は除去しない。
4. 必須列の存在を確認する。
5. 各行の形式を検証する。`date`、`sku`および4倉庫区分の列の値を検証し、不正な行は4倉庫区分とも登録対象から除外する。
6. `date + sku`による重複判定を行い、取込対象行を確定する。
7. `sku`がSKUマスタに存在しない場合は、SKU識別レコードを自動登録する。
8. 1行を4倉庫区分の在庫数へ分割する。
9. 取得区分が`手入力`の既存レコードを特定し、上書き対象から除外する。
10. 在庫数を追加または更新する。値が同一の既存レコードは更新しない。
11. 在庫基準日ごとに、直前の在庫基準日に存在し当該在庫基準日に存在しなかったSKUを消失件数として特定する。
12. 取込件数、更新件数、変更なし件数、消失件数、警告件数、エラー件数を取込履歴に記録する。
13. エラー・警告内容を利用者が確認できるようにする。

ファイルに含まれない在庫基準日のレコードは、本処理のいずれの段階でも更新・削除しない（[商品在庫保存データ 第6章](03.商品在庫保存データ.md)）。

## 2. 取込頻度

在庫取得システムは在庫を日次で出力するが、本システムへの取込頻度は未確定である（[商品在庫取込要件 第7章](01.商品在庫取込要件.md)）。日次在庫CSVは複数日分を含みうるため、取込頻度によらず次の要件を満たす。

- 取込済みの在庫基準日を含むファイルを取り込んでも、値が同一であれば在庫数を変化させない。
- 在庫取得システムで訂正した値は、同じ在庫基準日を含むファイルの再取込で反映する。
- 取込頻度が低いほど、在庫試算で採用する最新の在庫基準日が古くなる。鮮度は[在庫利用要件 第6章](04.在庫利用要件.md)により扱う。

販売実績の取込は出勤日の毎朝1回である（[販売実績取込要件の取込処理・運用要件 第2章](../販売実績取込要件/05.取込処理・運用要件.md)）。在庫も日次で取り込む場合は、販売実績と同じ運用に組み込む。実行担当者は、原則として本業務の担当者とする。

## 3. 初回取込

初回取込では、次を実施する。

- 在庫取得システムが出力できる範囲で、過去の在庫基準日を含む日次在庫CSVを取り込む。どこまで遡るかは未確定である（[商品在庫取込要件 第7章](01.商品在庫取込要件.md)）。
- 初回取込の最も古い在庫基準日より前の日付を基準日とする在庫試算は実行できない。

在庫取込ではSKUマスタの子ASINを参照しないため、在庫取込のために子ASINを整備する必要はない。子ASINはAmazon全注文レポートの取込のために整備する（[商品管理要件](../商品管理要件/01.商品管理要件.md)）。

## 4. 在庫取込の運用上の制約

- 取り込んだ在庫は、`date`の時点の値である。取込日時ではなく在庫基準日を在庫の時点として扱う。
- 日次在庫CSVが特定の日を含まない場合、その日の在庫は保持しない。前後の在庫基準日から補完しない。
- 在庫取得システムの出力に失敗した日がある場合は、在庫取得システム側で再出力したファイルを取り込む。本システムで在庫を推定して登録しない。
