# 日次在庫CSV取込要件

- 文書状態：改訂案
- 更新日：2026年10月1日
- 対象システム：商品在庫管理システム
- 実データ検証状況：日次在庫CSV 確認済み

本書は、在庫取得システムが出力する日次在庫CSVの取込要件を定める。4つの倉庫区分すべての在庫が対象である。  
在庫取得システムとの役割分担および共通の方針は[01.商品在庫取込要件](01.商品在庫取込要件.md)に、保存形式は[03.商品在庫保存データ](03.商品在庫保存データ.md)に定める。  
章構成は[販売実績取込要件](../販売実績取込要件/01.販売実績取込要件.md)の取込元別要件文書にそろえ、旧版の在庫取込元別要件とも対応させている。

## 1. 入力ファイル

| 項目 | 内容 |
| --- | --- |
| 取得元 | 在庫取得システム |
| ファイル形式 | CSV |
| 区切り文字 | カンマ |
| 文字コード | UTF-8（BOMなし） |
| 改行コード | LF |
| 項目名 | 1行目 |
| データ構造 | 1在庫基準日の1SKUにつき1行。4倉庫区分の在庫数を列として持つ |
| 列数 | 12列 |

1ファイルに複数の在庫基準日の行を含む。実データは8日分・2080行である。

実データでは値に引用符およびカンマを含む行は存在しない。ただし解釈は引用符付きCSVとして行い、引用符で囲まれた値を許容する。BOM付きのファイルも受け付け、BOMを列名に含めない。

## 2. 必須列・値の扱い

日次在庫CSVには、最低限次の列が必要である。すべての列名は前後の空白を除去してから照合する。

| 列名 | 用途 | 値の必須 |
| --- | --- | --- |
| `date` | 在庫基準日 | 必須 |
| `sku` | システム内商品コード | 必須 |
| `boss_own` | `BOSS自社倉庫`の販売可能在庫 | 必須 |
| `boss_rfc` | `RFC`の販売可能在庫 | 必須 |
| `amazon_own` | `Amazon自社倉庫`の販売可能在庫 | 必須 |
| `amazon_fba` | `FBA`の販売可能在庫 | 必須 |

上記以外の列は存在しなくても取込エラーとしない。列の並び順には依存せず、列名で特定する。値の必須条件を満たさない行の扱いは[取込エラー・警告 第2章](06.取込エラー・警告.md)に定める。

## 3. 取込対象

すべての行を在庫の取込対象とする。取込対象を限定するステータス列は存在しない。

## 4. 在庫基準日

`date`列の値を在庫基準日とする。形式は`YYYY-MM-DD`である。担当者は取込時に在庫基準日を指定しない。

- 同一ファイル内の`date`は複数の値をとりうる。在庫基準日ごとに独立して保存する。
- 実データの`date`は連続しておらず、土日・祝日に加えて平日（2026年9月17日）も欠ける（第12章）。行が存在しない日の在庫を前後の日から補完しない。
- 未来日の`date`を持つ行は登録しない（[取込エラー・警告 第2章](06.取込エラー・警告.md)）。

## 5. 倉庫区分

列名により倉庫区分を判定する。1行から4倉庫区分の在庫数を生成する。

| 列名 | 倉庫区分 |
| --- | --- |
| `boss_own` | `BOSS自社倉庫` |
| `boss_rfc` | `RFC` |
| `amazon_own` | `Amazon自社倉庫` |
| `amazon_fba` | `FBA` |

倉庫を追加する場合は、在庫取得システムの出力列の追加にあわせて本表と倉庫マスタに登録する。

## 6. 商品コードの解決

`sku`をそのままシステム内商品コードとして採用する。変換、表記の正規化およびSKUマスタの子ASINの参照は行わない。未登録SKUの扱いは[商品在庫取込要件 第6.2節](01.商品在庫取込要件.md)による。

## 7. 一意キー・重複行の扱い

ファイル内の一意キーは`date + sku`とする。

同一ファイル内に同一の一意キーが複数存在する場合は、2行目以降を登録せず行単位の取込エラーとする。どの行が正しいかを本システムでは判定できないため、最初の行だけは登録する。実データに重複は存在しない。

保存時の一意キーは`在庫基準日 + 倉庫区分 + システム内商品コード`である（[商品在庫保存データ 第3章](03.商品在庫保存データ.md)）。

## 8. 保持する在庫数量項目

4倉庫区分の列の値を、それぞれの倉庫区分の販売可能在庫として保存する。値の算出は在庫取得システムが行い、本システムでは加工しない（[商品在庫取込要件 第5.5節](01.商品在庫取込要件.md)）。

- 値は整数として解釈する。小数、数値以外の文字を含む値は行単位の取込エラーとする。
- 1行の4列のうち1列でも不正な場合は、当該行の4倉庫区分すべてを登録しない。同一行の一部の倉庫区分だけを登録すると、同一在庫基準日・SKUの倉庫区分間で在庫の有無が不揃いになるためである。

## 9. 取り込まない項目

| 列名 | 取り込まない理由 |
| --- | --- |
| `product_code` | 品番は商品マスタで管理する。実データでは`sku`の接頭辞と一致しない値（`flw-002`に属する`flw-001-002-1a`等）があり、CSVの値で品番の所属を判定しない |
| `brand` | 商品マスタで管理する属性である |
| `category` | 商品マスタで管理する属性である。実データでは21SKUで在庫基準日により値が異なる |
| `size` | 商品マスタで管理する属性である。実データでは同一SKUで空欄と`0`が在庫基準日により混在する |
| `free_stock` | 意味が未確認であり、4倉庫区分のいずれにも対応しない（[商品在庫取込要件 第7章](01.商品在庫取込要件.md)） |
| `ec_stock` | 意味が未確認であり、4倉庫区分のいずれにも対応しない（同上） |

## 10. 0在庫・マイナス在庫の扱い

- `0`は在庫0として登録する。行が存在しないこと（未取得）と区別する。
- 負値は`0`へ補正せず登録し、警告する（[取込エラー・警告 第3章](06.取込エラー・警告.md)）。実データに負値は存在しない。

## 11. セット商品の扱い

日次在庫CSVにはセット商品を識別する列が存在しない。セット商品を含むか、含む場合に構成品の在庫をどう表すかは在庫取得システムの出力仕様によるため、本システムでは`sku`を通常のSKUとして登録する。

## 12. 実データ検証結果

`参考/商品在庫取込データ/日次在庫.csv`で次を確認した。

| 確認項目 | 結果 |
| --- | --- |
| 文字コード・改行 | UTF-8（BOMなし）、LF。全2081行（項目名行を含む）が12列 |
| 在庫基準日 | 2026年9月16日、18日、24日、25日、28日、29日、30日、10月1日の8日分 |
| 1日あたりの行数 | 256行または264行。`si-07`の8SKUは3日分、`gg5099`の8SKUは1日分だけ存在する |
| SKU | 272件。26品番に属し、すべて旧BOSS各在庫数レポート（2026年8月27日出力）の`SKUコード`と完全一致。英大文字・空白を含む値はない |
| 一意キーの重複 | `date + sku`の重複なし |
| 在庫数量 | 4倉庫区分の列はすべて0以上の整数。空欄なし。4列とも`0`の行が88行 |
| `size` | 空欄44行、`0`が44行。いずれも同一SKUで在庫基準日により空欄と`0`が入れ替わる |

1日あたりの行数の変動から、在庫取得システムの出力対象SKUは在庫基準日により増減する。前日に存在したSKUが存在しない場合も、当該SKUの在庫を`0`とみなさない（[商品在庫保存データ 第6章](03.商品在庫保存データ.md)）。
