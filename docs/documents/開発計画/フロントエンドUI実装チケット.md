# フロントエンドUI実装チケット

- 文書状態：初版案
- 版数：0.1
- 作成日：2026年10月6日
- 更新日：2026年10月6日
- 対象システム：ECモール統合分析システム「Mall Insight」
- 参照資料：[ページ構成](../構成/ページ構成.md)、[要件定義書](../要件定義書.md)

## 1. 目的と範囲

設計書の分量が多く机上での見直しが困難であるため、全画面のフロントエンドUIをダミーデータで先行実装し、[ページ構成](../構成/ページ構成.md)の画面と仕様が想定どおり実装可能かを確認する。本書はその作業をチケット単位に分割したものである。バックエンド（API、DB、計算処理）は範囲外とする。

## 2. 現状（2026年10月6日時点）

| 区分 | 状態 |
| --- | --- |
| 実装済み | 共通シェル（ヘッダー・サイドバー・ログイン）、PG-010 ダッシュボード、PG-730 12か月在庫推移 |
| 未実装 | 上記以外の画面（共通の `PlaceholderView` を表示） |
| ダミーデータ | 各画面のファイル内に直接記述している |

実装と設計書の間に次の差異がある。FE-00で方針を決める。

1. ナビゲーションに PG-740 欠品・推奨発注一覧、PG-810 商品・SKUマスタ、PG-840 調達マスタが無い。[ページ構成](../構成/ページ構成.md)および[要件定義書](../要件定義書.md) 10.1 には残っている。
2. PG-730 の実装コメントに、設計書に無い次の決定が記載されている。
   - 欠品警告・過剰在庫警告を基準日から6か月後時点の試算結果で判定する。
   - 調達リードタイムと安全在庫日数を全SKU共通の固定値とする（調達マスタの簡素化）。
   - 商品名をマスタに持たない。ただし PG-510・PG-810 の表示項目には商品名が残っている。

## 3. 共通の完了条件

全チケットに次を適用する。

1. APIに接続せず、ダミーデータで画面が操作できる。
2. 画面IDと関連要件をコード内に明記する。
3. [ページ構成](../構成/ページ構成.md) 第6章の主な表示項目・主な操作がすべて画面上に存在する。
4. 仕様の不足、矛盾および未確定事項を第6章「設計書指摘一覧」に記録する。
5. `npm run check` が通る。

規模の目安は S=0.5日、M=1～2日、L=3日以上とする。

## 5. 進め方

1. FE-00で画面範囲を確定し、FE-01～FE-06で共通基盤を整える。
2. 業務導線の中核で仕様確認の効果が高い FE-41 → FE-50 → FE-60 → FE-71 → FE-82 を優先する。
3. 取込・マスタ・設定系は構造が単純なため、後続で並行して進める。
