# システム需要予測設計

- 文書状態：初版案
- 版数：0.3
- 作成日：2026年8月28日
- 更新日：2026年8月28日
- 対象システム：ECモール統合分析システム「Mall Insight」
- 参照資料：[要件定義書](../要件定義書.md) FR-010〜FR-018、FR-031、FR-040

本書は、システム需要予測の目的、全体像および全工程に共通する方針を定める。工程ごとの設計は、第4章に示す各文書に分割して記述する。

## 1. 目的

全SKUの販売実績を取り込み、一定の販売数量を満たして商品マスタへ登録された品番から売上上位品番を判定する。担当者が確定した20品番以内に属するSKUについて、将来12か月の需要見込みを自動で算出する。この値をシステム需要予測と呼び、在庫試算で使用する唯一の需要値とする（[要件定義書 FR-040、FR-042](../要件定義書.md)）。担当者が入力する年間販売目標は需要値として使用せず、差異の確認だけに使用する。

需要予測は次の3つを同時に満たす必要がある。

| 満たすこと | 設計上の対応 |
| --- | --- |
| 過去の売れ方を根拠にする | 補正済みの販売実績から平均日販、季節係数およびトレンド係数を算出する（[02](02.予測用実績の補正.md)〜[04](04.季節係数・トレンド係数.md)） |
| 商品ごとに当て方を変える | 6つの予測方式を過去データで競わせ、当たった方式を品番ごとに採用する（[05](05.予測モデルと需要予測の算出.md)・[06](06.バックテストとモデル選択.md)） |
| 後から根拠をたどれる | 使用データ、計算式、係数、算出日時を予測バージョンとして保存する（[08](08.予測バージョンと月次更新.md)） |

## 2. 予測の全体像

需要予測は次の順で算出する。番号は工程を示し、括弧内は詳細を定める文書である。

```markdown
全SKUの取込済み販売実績
  │
  ├─ 00.登録基準を満たす品番を商品マスタへ登録し、登録済み品番から
  │     売上上位品番を判定して担当者が20品番を確定する（FR-018・FR-042）
  │     ... 対象品番の選定バージョン・対象SKU
  │
  ├─ 01.対象SKUの実績を予測に使える形へ整える（02）
  │     欠品日・販売停止日を除く、異常値を判定する
  │     ... 補正済み実績・販売可能日数
  │
  ├─ 02.予測の材料を求める（03・04）
  │     平均日販・基準平均日販／季節係数／トレンド係数
  │
  ├─ 03.6つの方式でそれぞれ予測する（05）
  │
  ├─ 04.過去データで方式を採点し、品番ごとに1つ選ぶ（06）
  │
  ├─ 05.選んだ方式で12か月分の需要を算出する（05）
  │     実績が足りない品番は上位階層から補完する（07）
  │
  └─ 06.予測バージョンとして保存する（08）
        │
        ├─ 在庫試算：倉庫区分別へ按分して使用する
        │   （[在庫利用要件 第3.3節](../商品在庫取込要件/04.在庫利用要件.md)）
        └─ 目標比較：年間販売目標との差異を表示する（FR-041）
```

00で対象品番を確定した後、01〜06を毎月1回、月次予測更新としてまとめて実行する（[08](08.予測バージョンと月次更新.md)）。日々の取込のたびに予測を作り直すことはしない。

## 3. 予測の対象と粒度

| 項目      | 内容                                                                                  |
| ------- | ----------------------------------------------------------------------------------- |
| 対象      | [要件定義書: FR-042](../要件定義書.md) により担当者が確定した20品番以内に属する全SKU。<br>対象外品番のSKUについて新しい予測を作成しない |
| 粒度      | SKU×対象月。1SKUにつき12か月分の予測値を持つ                                                         |
| 方式選択の単位 | 品番。品番に属する全SKUへ同じ予測方式を適用する（[06 第3章](06.バックテストとモデル選択.md)）                             |
| 対象を決める版 | 対象品番の選定バージョン。予測バージョンへ関連付け、同じ選定版の対象SKUを過不足なく含める                                      |
| 期間      | 基準日の翌月から12か月先まで（ローリング予測）。会計年度の残期間は月別予測の合計として表示する                                    |
| 更新      | 暦月ごとに1回。ほかに臨時の再評価と手動予測補正がある                                                         |

倉庫区分別（`BOSS自社倉庫`、`RFC`、`Amazon自社倉庫`、`FBA`）の需要は、本設計では算出しない。SKU単位の需要予測に倉庫区分別需要構成比を掛けて求める設計であり、その方法は[在庫利用要件 第3.3節](../商品在庫取込要件/04.在庫利用要件.md)に定める。

## 5. 用語説明

[要件定義書 第5章](../要件定義書.md) の用語定義を、計算上の意味で言い換えたものである。正式な定義は要件定義書による。

| 用語            | 説明                                                                           |
| ------------- | ---------------------------------------------------------------------------- |
| 販売可能日数        | その商品が実際に売れる状態だった日数。欠品していた日は数えない。                                             |
| 平均日販          | 1日に平均何個売れたか。販売可能日数で割る。                                                       |
| 基準平均日販        | 直近の30日・60日・90日の平均日販を混ぜて1つにした値。直近の変化と落ち着いた傾向の折衷。                              |
| 季節係数          | その月が普段より売れるか売れないかを表す倍率。1.0が普段通り、1.3なら3割増し。<br>季節による影響が受けやすい商品に適用される（例：サングラス） |
| トレンド係数        | 商品全体が伸びているか落ちているかを表す倍率。1.1なら1割の伸び。<br>新商品などの売れ行きが変動しやすい商品に適用される。             |
| 予測候補モデル       | 需要の求め方そのもの。AIに限らず「30日平均を使う」も1つの方式                                            |
| バックテスト        | 過去のある時点に戻り、その時点までのデータだけで予測をやり直し、その後の実績と突き合わせて当たり外れを採点し、予測の精度を測定すること。         |
| MAE・WAPE・MAPE | 予測の精度を表す3つの基準項目。詳細は[06 第6章](06.バックテストとモデル選択.md)                              |
| 補完階層          | 係数や予測方式を、SKU・品番・カテゴリーのどの単位から取るかを決める仕組み。下位で実績が足りなければ上位の傾向を借りる                 |
| 予測バージョン       | いつ・どのデータ・どの係数で算出した予測かをひとまとめにした版                                              |

## 6. 共通方針

1. **需要と目標を混ぜない**
	- 年間販売目標は予測の入力に一切使用しない。季節係数、トレンド係数、モデル選択のいずれにも使わない。
2. **形は品番、水準はSKU**
	- 予測方式と季節係数は品番単位で決め、平均日販はSKU単位で持つ。
	- 1SKUの販売数量は月1〜2個の水準であり、SKU単位では方式も係数も定まらない（[06 第3章](06.バックテストとモデル選択.md)、[07 第3章](07.実績不足時の補完と例外商品.md)）。
3. **売れなかった理由を需要の減少と見なさない**
	- 欠品・販売停止で売れなかった期間は、平均日販の分母から除く（[02](02.予測用実績の補正.md)）。
4. **予測時点より後の情報を使わない**
	-  バックテストでは、実績だけでなく季節係数、トレンド係数、重みも起点時点の値で算出し直す（[06 第8章](06.バックテストとモデル選択.md)）。
5. **算出できないものを0にしない**
	- 予測対象SKUで実績なし、0除算または補完不能となった場合は「予測不能」として出力し、0個の需要として扱わない。商品マスタ未登録または対象外のSKUは予測レコードを作成しない（[07](07.実績不足時の補完と例外商品.md)、[09](09.予測エラー・警告.md)）。
6. **元の実績を書き換えない**
	- 補正は別データとして持ち、補正前後の両方を保持する（[02 第2章](02.予測用実績の補正.md)）。
7. **同じ入力からは同じ結果が出る**
	- 乱数や実行時刻に依存する計算を使用しない。再実行しても同じ予測値とモデル選択結果になること（[要件定義書 第12.4節](../要件定義書.md)）。
8. **導出できる値は保存しない：**
	- 保存するのは需要予測（SKU×対象月）、需要構成比、モデル選択結果および候補別精度に限る（[要件定義書 第10.3節](../要件定義書.md)、[08 第6章](08.予測バージョンと月次更新.md)）。
9. **予測出力と入力実績の範囲を混同しない**
	- 販売実績・在庫は全SKUについて取り込み、対象外SKUの実績を入力段階で除外しない。売上順位は商品マスタ登録済み品番から判定し、カテゴリー補完には商品マスタ登録済みかつカテゴリーを判定できるSKUだけを使用する。需要予測の出力は確定した対象品番のSKUに限定する。

## 8. 本設計の対象外

- SALE・広告強化・価格改定の施策補正（FR-013）。初期リリースの対象外とし、実績が蓄積した後に設計する。当面は手動予測補正で代替する（[05 第7章](05.予測モデルと需要予測の算出.md)）。
- 倉庫区分別の需要按分。[在庫利用要件](../商品在庫取込要件/04.在庫利用要件.md)に定める。
- 12か月在庫推移、欠品判定および推奨発注数の算出。[要件定義書 FR-060〜FR-063](../要件定義書.md)および[在庫利用要件](../商品在庫取込要件/04.在庫利用要件.md)に定める。
- 年間販売目標の登録・配分（FR-020〜FR-022）。
