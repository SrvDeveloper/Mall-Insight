# 予測バージョンと月次更新

- 文書状態：初版案
- 版数：0.4
- 作成日：2026年8月28日
- 更新日：2026年10月1日
- 対象システム：ECモール統合分析システム「Mall Insight」
- 参照資料：[要件定義書](../要件定義書.md) FR-018、FR-040、第10.3節

本書は、算出した需要予測をどの単位で保存し、いつ作り直すかを定める。全体の位置づけは[システム需要予測設計 第2章](01.システム需要予測設計.md)の工程06である。

## 1. この工程で決めること

予測は毎月変わる。古い予測を上書きすると、当時なぜその発注をしたのかが分からなくなる。ここでは次を定める。

- 1回分の予測をひとまとめにする単位（予測バージョン）
- 版を新しく作る場面と、作らない場面
- 毎月の更新手順

## 2. 予測バージョンに含めるもの

予測バージョンは、1回の算出でできた予測と、その算出条件をひとまとめにした版である。

| 区分 | 含める内容 |
| --- | --- |
| 結果 | SKU×対象月の需要予測値（12か月分）、予測不能の状態と理由 |
| 結果 | SKU×倉庫区分の需要構成比（[在庫利用要件 第3.3節](../商品在庫取込要件/04.在庫利用要件.md)） |
| 結果 | 品番ごとの選択モデル、補完階層、選択理由、候補別精度（[06 第11章](06.バックテストとモデル選択.md)） |
| 結果 | SKUごとに適用したモデルと、係数の補完階層 |
| 条件 | 基準日、対象期間、対象実績の範囲と取込日時 |
| 条件 | 対象品番の選定バージョン、対象品番数`P`、対象SKU数`T` |
| 条件 | 採用平均日販と期間別平均日販、適用した重み（[03 第7章](03.平均日販.md)） |
| 条件 | 係数バージョン、補完階層、使用年度（[04 第8章](04.季節係数・トレンド係数.md)） |
| 条件 | モデルバージョン、パラメータ設定の版 |
| 条件 | 算出日時、算出契機（月次更新・選定変更・臨時・手動補正） |

在庫試算は、実行時点の最新の確定済み予測バージョンを使用する。試算条件および結果は保存しない（[要件定義書 第10.3節](../要件定義書.md)）。

## 3. 版を作る契機

| 契機 | 版を作るか | 内容 |
| --- | --- | --- |
| 月次予測更新 | 作る | 暦月ごとに1回、ユーザーの操作により実行する |
| 対象品番の選定変更 | 作る | 追加品番を再評価し、新しい選定バージョンの対象SKUを揃えた完全な予測版を作る |
| 臨時の再評価 | 作る | 大幅な価格改定、販売チャネル追加、商品リニューアル等の登録後に実行する |
| 手動予測補正の登録 | 作る | 補正前後の値を保持する（[05 第7章](05.予測モデルと需要予測の算出.md)） |
| 画面表示のための再計算 | 作らない | 倉庫区分別需要予測、12か月在庫推移などの都度算出 |
| 設定値の変更 | 作らない | 次回の月次予測更新または臨時の再評価から適用する |
| 販売実績の日次取込 | 作らない | 実績は蓄積されるが、予測は作り直さない |

再評価前の予測値とモデル情報を上書きせず、新しい版として保存する（[要件定義書 FR-018](../要件定義書.md)）。

## 4. 月次予測更新

### 4.1 実行の前提

- 当月分までの販売実績の取込が完了していること。
- 対象品番が20品番以内で確定され、選定バージョンが作成されていること。
- 対象実績の最終取込日時を画面に表示し、担当者が確認したうえで実行する。
- 在庫の取込完了は前提としない。予測は在庫を使用しないためである。

### 4.2 手順

```text
⓪ 対象SKUの確定          （FR-042）選定バージョンから対象品番と所属SKUを確定する
① 予測用実績の補正      （02）対象SKUの補正済み実績と販売可能日数を再計算する
② 計算材料の算出        （03・04）平均日販・季節係数・トレンド係数を再計算する
③ バックテスト          （06）6候補モデルを12起点で採点する
④ モデル選択            （06）品番ごとに採用モデルを決め、所属SKUへ適用する
⑤ 需要予測の算出        （05・07）12か月分を算出し、補完・予測不能を確定する
⑥ 需要構成比の算出      （在庫利用要件 第3.3節）
⑦ 予測バージョンの確定  本書第2章の内容を保存する
```

- ⓪〜⑦は非同期の一括処理として実行し、進捗と完了を確認できるようにする（[要件定義書 第12.1節](../要件定義書.md)）。
- ①〜⑥の出力対象は、⓪で確定した対象SKUに限定する。ただしカテゴリー補完の集計元には、対象外SKUのうち商品マスタ登録済みで品番との対応およびカテゴリーを判定できるSKUの販売実績を使用できる。商品マスタ未登録、品番未設定またはカテゴリー未設定のSKUは使用しない。
- 途中で失敗した場合は予測バージョンを確定させない。確定前の中間結果を在庫試算から参照させない。
- 完了後、前回版との差が大きいSKUを一覧で確認できるようにする。

### 4.3 実行の制限

| 状況 | 扱い |
| --- | --- |
| 当月・同じ選定バージョンで正常完了済み | 同じ条件の月次予測更新を再実行しない。新たな予測バージョンを作らない |
| 当月に失敗して終了 | 再実行できる |
| 実行日 | 固定しない。当月の任意の日に実行できる |
| 選定変更・臨時の再評価・手動予測補正 | 上記の制限の対象外とする |

月次予測更新画面で、最終更新日時、対象実績の取込日時および当月実行済みかを確認できるようにする（[要件定義書 FR-018](../要件定義書.md)）。

### 4.4 実行しなかった場合

月次予測更新を実行しない月があっても、直近の予測バージョンをそのまま使用できる。ただし次を表示する。

- 予測バージョンの基準日からの経過日数
- 予測対象期間の残り月数。12か月分の予測のうち、経過した月は使用できない

基準日からの経過日数が閾値を超えた予測バージョンを在庫試算で使用する場合は警告する（[09](09.予測エラー・警告.md)）。

## 5. 臨時の再評価

次を登録した場合、月次予測更新を待たずに再評価できる。

- 対象品番の選定バージョンの変更
- 大幅な価格改定
- 販売チャネル（モール）の追加・終了
- 商品リニューアル
- 精度警告が発生し、モデルを切り替える場合

対象品番の選定変更では、追加された品番だけを再計算できるようにする。ただし新しい予測バージョンは部分版とせず、新しい選定バージョンに属する全対象SKUを含む完全な版として確定する。継続品番は、対象実績・基準日・設定・モデルバージョンが直前の有効な予測と同一の場合に限り、その結果を引き継ぐ。いずれかが異なる場合は継続品番も再計算する。選定から外れた品番の過去予測は削除せず、新しい版へは引き継がない。追加品番の予測が完了するまで、その選定バージョンによる在庫試算を実行できない。

その他の臨時の再評価も第4.2節と同じ手順で実行し、算出契機を「臨時」として記録する。対象品番を限定して再計算できるが、確定する予測バージョンには同じ選定バージョンの全対象SKUを含める。

## 6. 保存データと件数

担当者が確定した対象品番数を`P`（最大20）、対象品番に属するSKU数を`T`、倉庫区分4区分、予測期間12か月、候補モデル6種、起点12を前提とした件数である。`P`と`T`は対象品番の選定バージョンごとに実数を記録する。

| データ | 粒度 | 1版あたり件数 | 年間（12版） |
| --- | --- | --- | --- |
| 需要予測 | 対象SKU × 対象月 | `12T` | `144T` |
| 需要構成比 | 対象SKU × 倉庫区分 | `4T` | `48T` |
| 予測モデル選択結果 | 対象品番 | `P` | `12P` |
| 予測モデル候補別精度 | 対象品番 × 候補モデル | `6P` | `72P` |
| 適用係数（季節係数） | 対象品番 × 月 | `12P` | `144P` |
| バックテスト起点別評価明細 | 対象品番 × 候補モデル × 起点 | `72P` | `72P`（最新版のみ） |

- 最新版だけを保持する起点別評価明細を除く年間増加は`192T + 228P`件である。`P=20`の場合は`192T + 4,560`件となる。予測データの保持年数は販売実績と別に設定する必要がある。
- 倉庫区分別需要予測（対象SKU×倉庫区分×対象月、1版あたり`48T`件）は保存せず、需要予測と需要構成比の積で導出する（[要件定義書 第10.3節](../要件定義書.md)）。
- 起点別評価明細は最新のモデルバージョンだけを保持し、旧版は削除する。
- 需要予測、需要構成比およびモデル関連データは、選定された対象品番とその所属SKUだけを保存する。全SKUの販売実績および在庫データは、この件数削減の対象に含めない。

## 7. 再現性

- 同じ入力データ、設定およびモデルバージョンを指定した場合、同じ予測値とモデル選択結果を算出できる決定的な計算とする（[要件定義書 第12.4節](../要件定義書.md)）。
- 保持していない過去のバックテスト起点別評価明細は、厳密再現の対象外とする。
- 過去の予測バージョンを、最新の実績や設定で自動的に置き換えない。
- 予測バージョンを削除できるのは管理者だけとする。

## 8. 未確定事項

1. 予測バージョンの保持年数。全版を保持するか、月次更新の版だけを一定年数保持し、臨時・手動補正の版を短期で削除するか。
2. 前回版との差が大きいSKUを抽出する基準。
3. 予測バージョンの鮮度警告の閾値（基準日からの経過日数）。
4. 月次予測更新の実行画面の採番（[01 第9章](01.システム需要予測設計.md)）。
