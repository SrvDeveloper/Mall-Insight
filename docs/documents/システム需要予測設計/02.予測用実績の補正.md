# 予測用実績の補正

- 文書状態：初版案
- 版数：0.4
- 作成日：2026年8月28日
- 更新日：2026年10月1日
- 対象システム：ECモール統合分析システム「Mall Insight」
- 参照資料：[要件定義書](../要件定義書.md) FR-016、FR-014、FR-010、FR-050、FR-051、FR-052

本書は、取り込んだ販売実績を予測に使える形へ整える工程を定める。全体の位置づけは [システム需要予測設計 第2章](01.システム需要予測設計.md) の工程01である。補正の算出・保存対象は、予測バージョンが参照する選定バージョンの対象SKUとする。全SKUの販売実績は保持し、対象外または商品マスタ未登録であることを理由に削除・変更しない。ただし、売上順位の判定は商品マスタ登録済み品番、カテゴリー補完の集計元は商品マスタ登録済みかつカテゴリーを判定できるSKUに限定する。取り込んだ実績そのものの保存形式は [販売実績保存データ](../販売実績取込要件/04.販売実績保存データ.md) に定める。

## 1. この工程で決めること

実際の販売数量をそのまま需要として扱うと、在庫切れにより販売機会を失った数量が実績に反映されないため、需要を実態よりも低く見積もる可能性がある。

そのため、この工程では在庫状況を考慮し、以下の2つを算出する。

| 求めるもの            | 使い道              |
| ---------------- | ---------------- |
| 補正済み実績（日別の純販売数量） | 平均日販の分子、季節係数の基礎値 |
| 販売可能日数（日別の販売可否）  | 平均日販の分母          |

## 2. 3種類の実績を区別する

同じ「実績」でも次の3つは別の値であり、相互に上書きしない。

| 名称       | 内容                                                 | 保存                                                            |
| -------- | -------------------------------------------------- | ------------------------------------------------------------- |
| `取込値`    | 取り込んだままの販売数量                                       | `販売注文明細` に保存する（変更しない）                                         |
| `純販売数量`  | `取込値` から手動調整数量を差し引き、`販売計上状態 = 計上`の明細だけを対象とした値      | `販売注文明細` から算出する（[販売実績保存データ 第9章](../販売実績取込要件/04.販売実績保存データ.md)） |
| `補正済み実績` | `純販売数量` に、予測のための除外・補正を適用した値（[第3章](02.予測用実績の補正.md)） | `販売実績補正` に補正前後の両方を保存する（[要件定義書 第10.1節](../要件定義書.md)）           |

補正は元データを書き換えない。補正済み実績は予測の入力にだけ使用し、売上や販売実績の一覧表示には使用しない。

## 3. 補正の対象と順序

補正は次の順に適用する。順序を入れ替えない。

| 順   | 補正       | 内容                        | 元の値の扱い                           |
| --- | -------- | ------------------------- | -------------------------------- |
| 1   | 計上対象の絞込み | `販売計上状態 = 計上` 以外の明細を除外する  | 取込時点で判定済み                        |
| 2   | 手動調整の反映  | キャンセル・返品・返金の手動調整数量を差し引く   | 取込時点で反映済み                        |
| 3   | 販売不可日の除外 | 欠品日・販売停止日・発売日前・終売後を分母から除く | [第4章](02.予測用実績の補正.md)            |
| 4   | 異常値の判定   | 突出した日の販売数量を除外または上限で置換する   | [第6章](02.予測用実績の補正.md)            |
| 5   | 施策補正     | SALE・広告強化・価格改定の影響を分離する    | 初期リリース対象外（[第7章](02.予測用実績の補正.md)） |

キャンセル・返品・返金は手動反映を基本とするため、販売実績に未反映の事象が存在しうる（[要件定義書 第13章](../要件定義書.md)）。未反映分を予測側で推定・補正しない。

## 4. 販売可能日数

### 4.1 定義

販売可能日数は、対象期間の暦日数から、その商品を売れる状態になかった日を差し引いた日数である。

```text
販売可能日数 = 対象期間の暦日数 - 除外日数
```

除外する日は次のとおりとする。

| 除外する日 | 判定の根拠           |
| ----- | --------------- |
| 欠品日   | 商品マスタに登録された欠品期間 |
| 販売停止日 | モール側で出品を停止していた日 |
| 発売日前  | 商品マスタの発売日より前の日  |
| 終売後   | 商品マスタの終売日より後の日  |

判定はSKU単位で行う。倉庫区分別に平均日販を求める場合は、当該倉庫が欠品していた日をその倉庫の分母から除く（[在庫利用要件 第3.2節](../商品在庫取込要件/04.在庫利用要件.md)）。

欠品・販売停止期間は、商品マスタでSKU×倉庫区分単位の期間履歴として管理する。発売日および終売日そのものは販売可能日として扱い、販売開始直後および終売直前の実績も採用する。販売開始後の実績が不足して平均日販を算出できない新商品は、実績を除外するのではなく [07 第5章](07.実績不足時の補完と例外商品.md) の新商品として扱う。カテゴリーから補完するのは予測方式、季節係数およびトレンド係数であり、販売数量の水準である平均日販は補完しない。

### 4.2 欠品日を判定するための入力

在庫は日次在庫CSVに含まれる在庫基準日ごとに取り込むが、取込頻度は未確定であり（[取込処理・運用要件 第2章](../商品在庫取込要件/05.取込処理・運用要件.md)）、日次在庫CSVにも含まれない日がある（[日次在庫CSV取込要件 第4章](../商品在庫取込要件/02.日次在庫CSV取込要件.md)）。したがって、取り込んだ在庫だけでは、最新の在庫基準日より後および在庫基準日の間の欠品日を判定できない。不足しているのは、在庫基準日以降の在庫の増減を追うための入力である。本設計では次の4つを入力とする。

| 入力          | 内容                                                                             | 位置づけ                                               |
| ----------- | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| 欠品・販売停止期間   | 開始日、終了日、区分（`欠品` ／ `販売停止`）、倉庫区分、理由                                              | 販売可能日数から除外する日の判定根拠。                             |
| 在庫確認値（現在庫数） | 担当者が任意の日に確認した販売可能在庫、確認日、倉庫区分。                                                 | 日次推定の新しい起点。取り込んだ在庫の在庫基準日とは区別する。                    |
| 補充実績        | 在庫補充または庫間移動により在庫が増減した日付と数量、区分（`在庫補充` ／ `庫間移動入庫` ／ `庫間移動出庫`）、倉庫区分。数量は正の整数で入力する。 | 起点以降の増減分。                                          |
| 日次の純販売数量    | 販売実績から `出荷倉庫` 別に集計する                                                           | 起点以降の減少分（[在庫利用要件 第3.1節](../商品在庫取込要件/04.在庫利用要件.md)） |

在庫基準日は取り込んだ在庫が成立した日（日次在庫CSVの`date`）とし、在庫確認値の入力では変更しない。在庫確認値は日次推定のための観測値として、SKU、倉庫区分、確認日、販売可能在庫、登録者および登録日時を保持する。日次在庫CSVに含まれない日付を在庫基準日として登録する運用は行わない。在庫確認値の入力はPG-620から行う。

補充実績は入荷予定とは別データとして保持し、入荷予定を使用しない場合も単独で登録できるものとする。入荷予定の確度を `入荷済` へ変更する際は、SKU、倉庫区分および予定数量を初期表示し、実際の補充日と数量を確認または修正して区分`在庫補充` の補充実績を登録できるようにする。入荷予定から登録した補充実績は元の入荷予定と関連付け、登録済みかを確認できるようにする。詳細は [要件定義書 FR-051、FR-052](../要件定義書.md) による。

### 4.3 日次推定在庫による判定

上記の入力から、SKU×倉庫区分ごとに日単位の推定在庫を求める。

```text
起点 = 対象日以前で最も新しい在庫確認値の確認日または在庫取込の在庫基準日
起点在庫 = 起点として採用した在庫確認値または在庫取込の販売可能在庫

日次推定在庫(d)
  = 起点在庫
  + Σ在庫補充数(起点日の翌日〜d)
  + Σ庫間移動入庫数(起点日の翌日〜d)
  - Σ庫間移動出庫数(起点日の翌日〜d)
  - Σ純販売数量(起点日の翌日〜d)
```

補充実績の数量は正の整数として扱い、区分が `在庫補充` または `庫間移動入庫` の場合は加算、 `庫間移動出庫` の場合は減算する。

- 日次推定在庫が0以下の日を欠品の警告対象とする。判定はSKU×倉庫区分単位で行う。
- 起点は対象日ごとに最も新しいものを採用する。起点が新しいほど誤差の累積は小さい。
- 在庫確認値を入力した日は、それ以前の推定値との差を繰り越さず、確認値を新しい起点在庫とする。推定値と確認値の差は通常発生しうるため、差異そのものは警告しない。
- 起点として採用した販売可能在庫または在庫確認値が0以下の場合は、その起点日を欠品期間の開始日とする。起点より前へは遡及しない。

販売可能日数から除外するのは、商品マスタに登録された欠品・販売停止期間だけとする。日次推定在庫は欠品日を自動確定するためには使用せず、次の運用で登録内容を確認するために使用する。

1. 日次推定在庫が0以下になった場合、担当者へ欠品の可能性を警告し、在庫確認値の入力を促す。
2. 入力した在庫確認値が正の場合は欠品期間を登録せず、その確認値から日次推定を再開する。
3. 入力した在庫確認値が0以下の場合は、確認日を開始日として商品マスタへ欠品期間を登録する。欠品解消後は終了日を登録する。
4. 販売停止は日次推定在庫から判断せず、実際の停止期間を商品マスタへ登録する。

補充実績に登録漏れがある場合、 `在庫補充` または `庫間移動入庫` の漏れでは推定在庫が実際を下回り、 `庫間移動出庫` の漏れでは実際を上回る。日次推定を欠品日の自動確定に使用せず、在庫確認を促す警告にとどめるのはこのためである。

補充実績の保持項目および入荷予定との連携は [要件定義書 FR-051、FR-052および第10.1節](../要件定義書.md) に定める。

### 4.4 除外による分母の縮小

除外の結果、販売可能日数が0または極端に少なくなる場合がある。対応は次のとおりとする。

- 販売可能日数が0の期間は平均日販を算出しない（[03 第5章](03.平均日販.md)）。
- 0除算の結果を0または無限大として扱わない。
- 対象期間の半分以上が除外日である場合は平均日販を算出せず、当該SKUを予測不能とする（[09](09.予測エラー・警告.md)）。欠品・販売停止の影響が大きく、残った日だけでは通常の需要水準を代表できないためである。

## 5. 補正の効果（例）

直近30日のうち5日間欠品し、25日間で60個販売したSKUの例を示す。

| 求め方 | 分子 | 分母 | 平均日販 | 30日換算の需要 |
| --- | --- | --- | --- | --- |
| 補正しない | 60個 | 30日 | 2.0個 | 60個 |
| 補正する | 60個 | 25日 | 2.4個 | 72個 |

補正しない場合、欠品によって売れなかった12個分だけ需要を低く見積もる。この状態で発注すると欠品が繰り返される。補正はこれを避けるために行う。

## 6. 異常値の判定

1日だけ突出した販売数量は、その後も続く需要とは限らない。次の条件をいずれも満たす日を異常値の候補とする。

```text
当日の純販売数量 > 同一SKUの直近90日の日別純販売数量の中央値 × 5
かつ 当日の純販売数量 > 10個
```

- 判定は日単位、SKU単位で行う。
- 中央値が0の場合は倍率の条件を適用せず、個数の条件だけで判定する。
- 候補は自動で除外せず、警告として提示し、担当者が除外・上限置換・そのまま採用のいずれかを選ぶ。
- 除外または置換した場合は、対象日、補正前後の値、区分および理由を`販売実績補正`へ保存する。
- 倍率と個数の閾値は設定値とする（[01 第7章](01.システム需要予測設計.md)）。

法人のまとめ買いのように、需要として妥当な突出もある。自動除外を既定としないのはこのためである。

## 7. 施策の影響

SALE、広告強化および価格改定による増減の分離（FR-013）は初期リリースの対象外である。当面は次のとおり扱う。

- 施策期間の販売数量をそのまま補正済み実績とする。施策による増加分を通常需要から差し引かない。
- 施策が予測に与えた影響が大きいと担当者が判断した場合は、手動予測補正で調整する（[05 第7章](05.予測モデルと需要予測の算出.md)）。
- 施策期間を実績から一律に除外しない。除外すると、毎年実施している施策の需要まで消える。
